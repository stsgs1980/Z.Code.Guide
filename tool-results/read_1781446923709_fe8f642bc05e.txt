    43→    43→## 1. Что такое ZCode 3.0
    44→    44→
    45→    45→> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome)
    46→    46→
    47→    47→ZCode — это **Agentic Development Environment (ADE)**, среда разработки, построенная вокруг AI-агента. Ключевая идея: вы описываете задачу на естественном языке, а Agent сам планирует, пишет код, тестирует и проверяет. В отличие от обычного автодополнения, Agent работает **долго и стабильно** — от постановки задачи до финальной проверки.
    48→    48→
    49→    49→### Две ключевые силы ZCode
    50→    50→
    51→    51→| Сила | Описание |
    52→    52→|---|---|
    53→    53→| **Длинные задачи (Long Horizon Tasks)** | Agent держит контекст от планирования до верификации — понимание требований, файлы, терминал, браузер, Git — всё в одной задаче |
    54→    54→| **Стабильность** | Саморазработанный ZCode Agent не теряет нить выполнения даже в многочасовых задачах с сотнями шагов |
    55→    55→
    56→    56→### Основные возможности
    57→    57→
    58→    58→- **Длинные задачи**: в одном таске — понимание требований, планирование, код, верификация, Review
    59→    59→- **Стабильный контекст**: файлы + терминал + браузер + режимы выполнения + Git — Agent ничего не забывает
    60→    60→- **Собственный Agent-флоу**: задачи, права, контекст, вызовы инструментов и Review — всё вокруг ZCode Agent
    61→    61→- **Мультиустройственное продолжение**: десктоп, мобильный Remote и Feishu/WeChat Bot — один и тот же таск на всех
    62→    62→- **Безопасность**: опасные команды, изменение файлов и высокопривилегированные действия — через подтверждение
    63→    63→- **Расширяемость**: Skills, Commands, Subagents, Plugins, MCP-серверы — настраивайте Agent под свою команду

   104→   104→## 3. API Key Setup — подключение моделей
   105→   105→
   106→   106→> **Источник:** [ZCode Docs — Configuration (API Key Setup)](https://zcode.z.ai/en/newdocs/configuration)
   107→   107→
   108→   108→ZCode поддерживает три способа подключения AI-сервисов:
   109→   109→
   110→   110→| Способ | Описание |
   111→   111→|---|---|
   112→   112→| **BigModel** | Аккаунт Zhipu — для Китая. Поддержка GLM Coding Plan, ресурсные пакеты, предоплата |
   113→   113→| **Z.AI** | Для международных пользователей. USD-ценообразование, бесплатная дневная квота |
   114→   114→| **Сторонние провайдеры** | Любой сервис, совместимый с протоколами Anthropic / OpenAI |
   115→   115→
   116→   116→### Рекомендуемый вариант
   117→   117→
   118→   118→**Для международных пользователей:** подпишитесь на GLM Coding Plan через Z.AI (USD-ценообразование) — получите доступ к GLM-5.2 с бесплатной дневной пробной квотой.
   119→   119→
   120→   120→**Для пользователей из Китая:** подпишитесь через BigModel — те же модели, но с более выгодной ценовой политикой.
   121→   121→
   122→   122→### Точки входа для настройки
   123→   123→
   124→   124→**Способ 1: Экран приветствия при первом запуске**
   125→   125→
   126→   126→При первом открытии ZCode (если нет подключённых моделей) предложит:
   127→   127→- **Continue with Z.ai** — авторизация через аккаунт Z.AI
   128→   128→- **Continue with BigModel** — авторизация через Zhipu BigModel
   129→   129→- **Use API key** — ввести ключ вручную и перейти к настройкам моделей
   130→   130→
   131→   131→После выбора Z.ai или BigModel откроется процесс авторизации. При успешной аутентификации аккаунт привязывается автоматически.
   132→   132→
   133→   133→**Способ 2: Селектор моделей**
   134→   134→
   135→   135→После входа в ZCode кликните на имя модели в поле чата → **Manage Models** внизу списка → откроется панель **Settings -> Model Settings**.
   136→   136→
   137→   137→### Подключение BigModel
   138→   138→
   139→   139→1. Откройте панель Model Settings
   140→   140→2. Выберите **BigModel** из списка провайдеров слева
   141→   141→3. Подключите аккаунт и включите переключатель
   142→   142→4. Используйте переключатель в правом верхнем углу для выбора режима: **Coding Plan** или **API Key**
   143→   143→
   144→   144→**Бесплатная пробная квота:** новые пользователи получают trial-план сразу при подключении BigModel — без оплаты, с бесплатной дневной квотой для флагманских GLM-моделей. Страница провайдера показывает текущий баланс и использование в реальном времени.
   145→   145→
   146→   146→**Подписка на Coding Plan внутри ZCode:** на странице BigModel доступны планы GLM Coding (Lite / Pro / Max) с ежемесячной, квартальной и годовой оплатой. Можно завершить покупку прямо в приложении.
   147→   147→
   148→   148→**Подключение через API Key:**
   149→   149→1. Переключите режим подключения на **API Key**
   150→   150→2. Base URL по умолчанию: `https://open.bigmodel.cn/api/anthropic`
   151→   151→3. Введите API-ключ с платформы Zhipu
   152→   152→4. Модели по умолчанию: GLM-5.2, GLM-5-Turbo, GLM-5V-Turbo
   153→   153→5. Нажмите **Add Model** для добавления других моделей
   154→   154→
   155→   155→### Подключение Z.AI
   156→   156→
   157→   157→Z.AI — вариант для международных пользователей. Настройка аналогична BigModel:
   158→   158→1. Откройте панель Model Settings
   159→   159→2. Выберите **Z.ai** из списка провайдеров
   160→   160→3. Подключите аккаунт и включите переключатель
   161→   161→4. Переключатель Coding Plan / API Key в правом верхнем углу
   162→   162→
   163→   163→Base URL для API Key: `https://api.z.ai/api/anthropic`
   164→   164→

   187→   187→### Проверка настройки

   193→   193→## 4. Интерфейс — что где находится
   194→   194→
   195→   195→> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome) + [ZCode Homepage](https://zcode.z.ai)
   196→   196→
   197→   197→### Рабочее пространство (Workspace)
   198→   198→
   199→   199→```
   200→   200→+-------------------------------------------------------------+
   201→   201→|  Модель: GLM-5.2 | Max | Thought Level | Настройки чата     |
   202→   202→+----------+----------------------------+---------------------+
   203→   203→|          |                            |                     |
   204→   204→|  Файлы   |      Чат с Agent          |  Git tools          |
   205→   205→|  +       |                            |  + Goal             |
   206→   206→|  Задачи  |  Agent: «Создаю API...»   |                     |
   207→   207→|  по      |                            |  Changes:           |
   208→   208→|  датам   |  [файл] [терминал]        |  +734 -7            |
   209→   209→|          |                            |  Commit             |
   210→   210→|          |                            |                     |
   211→   211→+----------+----------------------------+---------------------+
   212→   212→|  Терминал (zsh / bash)                                      |
   213→   213→|  user@project % _                                           |
   214→   214→+-------------------------------------------------------------+
   215→   215→```
   216→   216→
   217→   217→### Элементы интерфейса
   218→   218→
   219→   219→| Элемент | Расположение | Что делает |
   220→   220→|---|---|---|
   221→   221→| **Боковая панель (левая)** | Слева | Дерево файлов + таймлайн задач, сгруппированных по дате |
   222→   222→| **Центральная область** | Центр | Чат с Agent + просмотр/редактирование кода |
   223→   223→| **Нижняя панель** | Внизу | Терминал (zsh/bash) |
   224→   224→| **Правая панель** | Справа | Git-инструменты (ветки, коммиты) + Goal (цели) + Changes (изменения) |
   225→   225→| **Верхняя строка чата** | Верх | Выбор модели, режим рассуждений, режим стриминга |
   226→   226→| **Иконка телефона** | Левый нижний угол | Mobile Remote Control (QR-код для подключения) |
   227→   227→| **Аватар** | Левый нижний угол | Меню: Feedback, настройки и т.д. |
   228→   228→| **Поле ввода чата** | Внизу центра | Ввод инструкций, `/` команды, `$` навыки, `@` подагенты |

   232→   232→## 5. Работа с ZCode Agent — базовый рабочий процесс
   233→   233→
   234→   234→> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome) + [Z.AI Best Practices](https://docs.z.ai/devpack/resources/best-practice)
   235→   235→
   236→   236→### Простая задача
   237→   237→
   238→   238→1. Откройте чат: **Cmd+N** (Mac) / **Ctrl+N** (Win) → «New Task»
   239→   239→2. Напишите инструкцию на естественном языке
   240→   240→3. Agent автоматически: исследует проект, создаст файлы, напишет код, запустит проверки
   241→   241→4. Следите за прогрессом в реальном времени
   242→   242→
   243→   243→### Что делает Agent в процессе
   244→   244→
   245→   245→| Шаг | Что происходит |
   246→   246→|---|---|
   247→   247→| **Exploring** | Agent исследует проект: ищет файлы, читает структуру |
   248→   248→| **Planning** | Составляет план: какие файлы создать/изменить |
   249→   249→| **Writing** | Пишет код, создаёт файлы |
   250→   250→| **Running** | Выполняет команды в терминале (npm install, npm test и т.д.) |
   251→   251→| **Verifying** | Проверяет результат: запускает тесты, линтер |
   252→   252→| **Reviewing** | Показывает финальные изменения: +N строк, -M строк |
   253→   253→
   254→   254→### Как давать инструкции Agent — 4 элемента эффективного промпта
   255→   255→
   256→   256→В сложном проекте эффективное описание задачи обычно включает четыре элемента:
   257→   257→
   258→   258→| Элемент | Описание | Пример |
   259→   259→|---|---|---|
   260→   260→| **Goal** | Что нужно построить или изменить | «Исправь баг авторизации» |
   261→   261→| **Context** | Релевантные файлы, ошибки, документация | «Файл auth.ts, строка 42, ошибка E401» |
   262→   262→| **Constraints** | Ограничения: стандарты, архитектура, зависимости | «Используй JWT, не меняй схему БД» |
   263→   263→| **Done when** | Критерий завершения | «Тесты auth.test.ts проходят» |
   264→   264→
   265→   265→**Хорошо:** «Исправь баг авторизации в auth.ts (строка 42, ошибка E401). Используй JWT, не меняй схему БД. Готово, когда auth.test.ts проходит.»
   266→   266→
   267→   267→**Плохо:** «Почини авторизацию»

   271→   271→## 6. Режимы выполнения (Execution Modes)
   272→   272→
   273→   273→> **Источник:** [ZCode Docs — Goal Mode](https://zcode.z.ai/en/newdocs/goal) (раздел «Combine with execution modes»)
   274→   274→
   275→   275→ZCode Agent поддерживает несколько режимов выполнения, которые определяют, сколько действий требуют подтверждения:
   276→   276→
   277→   277→| Режим | Описание | Когда использовать |
   278→   278→|---|---|---|
   279→   279→| **Full Access / Auto Edit** | Agent выполняет действия без постоянных подтверждений | Для длинных задач, Goal Mode — минимум прерываний |
   280→   280→| **По умолчанию** | Опасные действия требуют подтверждения | Для повседневной разработки |
   281→   281→| **Strict / Manual** | Каждое действие требует подтверждения | Для критических изменений |
   282→   282→
   283→   283→**Как переключить:** нажмите **Shift+Tab** (когда фокус в поле ввода чата) для циклического переключения режимов.
   284→   284→
   285→   285→**Совет:** Для длинных goal-driven задач комбинируйте Goal Mode с Full Access — это минимизирует прерывания и позволяет итерациям идти непрерывно.
   286→   286→
   287→   287→---
   288→   288→
   289→   289→## 7. Goal Mode — режим целей для сложных задач
   290→   290→
   291→   291→> **Источник:** [ZCode Docs — Goal Mode](https://zcode.z.ai/en/newdocs/goal)
   292→   292→
   293→   293→### Когда использовать
   294→   294→
   295→   295→- Задача легко описывается одним предложением, но требует много итераций
   296→   296→- Примеры: «Отрефактори весь модуль, чтобы тесты проходили», «Исправь все TypeScript-ошибки», «Получи Lighthouse-оценку выше 90»
   297→   297→
   298→   298→### Как работает
   299→   299→
   300→   300→1. Вы ставите цель через `/goal`
   301→   301→2. Agent работает итеративно — в конце каждой итерации **автоматически проверяет** цель
   302→   302→3. Если цель не достигнута — начинается следующая итерация
   303→   303→4. Задача завершается только когда цель **верифицирована как выполненная**
   304→   304→5. Вам не нужно повторно писать «продолжай» — Agent продолжает сам
   305→   305→
   306→   306→### Команды Goal Mode
   307→   307→
   308→   308→| Команда | Описание |
   309→   309→|---|---|
   310→   310→| `/goal <objective>` | Установить цель сессии |
   311→   311→| `/goal replace <objective>` | Заменить текущую цель |
   312→   312→| `/goal pause` | Поставить цель на паузу |
   313→   313→| `/goal resume` | Возобновить цель |
   314→   314→| `/goal clear` | Удалить цель |
   315→   315→
   316→   316→### Совет по формулировке цели
   317→   317→
   318→   318→Делайте цель **конкретной и проверяемой**:  
   319→   319→«Исправь все TypeScript-ошибки компиляции и добейся, чтобы `pnpm test` проходил» — лучше, чем «исправь ошибки».
   320→   320→
   321→   321→### Что происходит после установки цели
   322→   322→
   323→   323→1. **Карточка цели** появляется в панели сводки (правый верхний угол) — статус (active/paused/complete), затраченное время, токены, количество итераций
   324→   324→2. **Автоматическая верификация** после каждой итерации
   325→   325→3. **Можно вмешаться в любой момент**: заменить цель, поставить на паузу, очистить
   326→   326→
   327→   327→---
   328→   328→
   329→   329→## 8. Command — встроенные и пользовательские команды
   330→   330→
   331→   331→> **Источник:** [ZCode Docs — Command](https://zcode.z.ai/en/newdocs/commands)
   332→   332→
   333→   333→### Встроенные команды
   334→   334→
   335→   335→| Команда | Назначение |
   336→   336→|---|---|
   337→   337→| `/goal` | Показать, установить, заменить, приостановить, возобновить или очистить цель текущей сессии |
   338→   338→| `/compact` | Сжать контекст текущего разговора с сохранением ключевой информации — полезно для продолжения длинных бесед |
   339→   339→
   340→   340→### Как использовать
   341→   341→
   342→   342→Введите `/` в поле ввода — откроется панель команд, организованная по группам **Commands** и **Skills**. Продолжайте печатать для фильтрации.
   343→   343→
   344→   344→### Создание пользовательской команды
   345→   345→
   346→   346→1. Откройте **Settings -> Commands**
   347→   347→2. Нажмите **Create new command**
   348→   348→3. Заполните поля:
   349→   349→
   350→   350→| Поле | Описание |
   351→   351→|---|---|
   352→   352→| **Scope** | User (доступно во всех workspace) или Workspace (только текущий проект) |
   353→   353→| **Name** | Имя команды, вызывается как `/command-name` |
   354→   354→| **Description** | Краткое описание, отображается в пикере команд |
   355→   355→| **Argument hint** | Подсказка параметра, например `<file-path>` |
   356→   356→| **Prompt** | Содержимое промпта, отправляемое Agent при запуске команды |
   357→   357→
   358→   358→Команды хранятся как `.md`-файлы в `~/.zcode/commands/` (на уровне пользователя) или в директории проекта (на уровне workspace).
   359→   359→
   360→   360→### Импорт команд из внешних Agent
   361→   361→
   362→   362→Если у вас есть команды в Claude Code или другом Agent — не нужно создавать их заново:
   363→   363→1. Откройте **Commands** в настройках ZCode
   364→   364→2. Нажмите **Import commands from external Agent** в правом верхнем углу
   365→   365→3. Выберите нужные команды и подтвердите
   366→   366→
   367→   367→### Когда использовать Command vs Skill
   368→   368→
   369→   369→- **Command** — для простого сохранённого промпта
   370→   370→- **Skill** — когда нужен полный рабочий метод с шаблонами, чеклистами, примерами
   371→   371→
   372→   372→---
   373→   373→
   374→   374→## 9. Skill — переиспользуемые рабочие инструкции
   375→   375→
   376→   376→> **Источник:** [ZCode Docs — Skill](https://zcode.z.ai/en/newdocs/skill)
   377→   377→
   378→   378→### Что это
   379→   379→
   380→   380→Skill — это переиспользуемая рабочая инструкция, определяемая файлом `SKILL.md`. Описывает, когда навык используется, как Agent должен работать и какой результат ожидается.
   381→   381→
   382→   382→### Управление навыками
   383→   383→
   384→   384→Откройте **Settings -> Skills** — каждая строка показывает имя навыка, источник, описание и переключатель включения.
   385→   385→
   386→   386→- Поиск навыков по имени
   387→   387→- Включение/выключение переключателем
   388→   388→- **New Skill** в правом верхнем углу — Agent поможет создать навык прямо в чате
   389→   389→
   390→   390→### Создание навыка
   391→   391→
   392→   392→Навык — это директория с файлом `SKILL.md` внутри:
   393→   393→
   394→   394→```
   395→   395→~/.zcode/skills/<skill-name>/SKILL.md
   396→   396→```
   397→   397→
   398→   398→Минимальный `SKILL.md`:
   399→   399→
   400→   400→```markdown
   401→   401→---
   402→   402→name: code-review-checklist
   403→   403→description: Review code changes with a focused checklist for correctness, regressions, tests, and maintainability.
   404→   404→---
   405→   405→
   406→   406→# Code Review Checklist
   407→   407→
   408→   408→Use this skill when reviewing a pull request, merge request, or local diff.
   409→   409→
   410→   410→Focus on correctness, regressions, missing tests, risky API changes, and maintainability.
   411→   411→```
   412→   412→
   413→   413→После создания: **Settings -> Skills -> Refresh** — навык появится в списке.
   414→   414→
   415→   415→### Импорт навыков из внешних Agent
   416→   416→
   417→   417→Поддерживается импорт из Claude Code, Codex CLI, OpenClaw, Augment, Windsurf:
   418→   418→
   419→   419→1. **Settings -> Skills** -> нажмите иконку **Import** в правом верхнем углу
   420→   420→2. ZCode просканирует директории внешних Agent и покажет доступные навыки
   421→   421→3. Выберите навыки и режим импорта:
   422→   422→   - **Symlink** — связь с внешней директорией (изменения синхронизируются, но зависит от пути)
   423→   423→   - **Copy** — независимая копия (без синхронизации с источником)
   424→   424→4. Выберите цель импорта: **Global** (на уровне пользователя) или **Project** (текущий workspace)
   425→   425→
   426→   426→### Использование навыка в чате
   427→   427→
   428→   428→Введите `$` в поле ввода и выберите навык. Навык появится как тег, после которого можно продолжить запрос:
   429→   429→
   430→   430→```
   431→   431→$code-review-checklist review my current changes
   432→   432→$release-notes write release notes for this change set
   433→   433→```
   434→   434→
   435→   435→### Что стоит сделать навыком
   436→   436→
   437→   437→- Задача повторяется: code review, API debugging, release notes, test reports
   438→   438→- Команда ожидает единообразный формат вывода
   439→   439→- Рабочий процесс требует фоновых знаний, чеклистов, шаблонов или примеров
   440→   440→- Возможность будет переиспользована в разных проектах
   441→   441→
   442→   442→---

   444→   444→## 10. Subagents — подагенты для делегирования задач
   445→   445→
   446→   446→> **Источник:** [ZCode Docs — Subagents](https://zcode.z.ai/en/newdocs/subagents)
   447→   447→
   448→   448→### Что это
   449→   449→
   450→   450→Subagents — специализированные роли, подготовленные для Agent. Вы можете превратить повторяющиеся задачи (code review, отладка тестов, release notes, проверка UI) в подагенты, чтобы активный Agent мог делегировать им целенаправленную работу.
   451→   451→
   452→   452→### Использование в чате
   453→   453→
   454→   454→Введите `@` в поле ввода и выберите роль из группы **Agents**:
   455→   455→
   456→   456→```
   457→   457→@zcode-reviewer проверь текущие изменения на риск регрессии
   458→   458→@zcode-test-helper найди, почему этот тест падает
   459→   459→```
   460→   460→
   461→   461→### Настройка подагентов
   462→   462→
   463→   463→Подагенты определяются как Markdown-файлы:
   464→   464→
   465→   465→- **На уровне пользователя** (доступны во всех workspace): `~/.zcode/cli/agents/`
   466→   466→- **На уровне workspace** (только текущий проект): `<workspace>/.zcode/cli/agents/`
   467→   467→
   468→   468→Каждый подагент — `.md`-файл с опциональным YAML frontmatter + системный промпт:
   469→   469→
   470→   470→```markdown
   471→   471→---
   472→   472→name: zcode-reviewer
   473→   473→description: Check changes for regression risk before committing
   474→   474→color: "#3b82f6"
   475→   475→model: glm-5.2
   476→   476→tools: Read, Grep, Bash
   477→   477→---
   478→   478→
   479→   479→You are a code-review subagent focused on regression risk, edge cases, and test coverage…
   480→   480→```
   481→   481→
   482→   482→**Поля frontmatter:**
   483→   483→
   484→   484→| Поле | Описание |
   485→   485→|---|---|
   486→   486→| `name` | 3-50 символов, буквы, цифры и дефисы |
   487→   487→| `description` | Когда использовать — управляет автоматическим делегированием |
   488→   488→| `color` (опционально) | Акцентный цвет в UI, например `#3b82f6` |
   489→   489→| `model` (опционально) | Конкретная модель; пусто = текущая модель сессии |
   490→   490→| `tools` (опционально) | Ограничение доступных инструментов |
   491→   491→
   492→   492→### Подагенты из плагинов
   493→   493→
   494→   494→Подагенты также могут предоставляться плагинами. После включения плагина роли появляются в списке автоматически (с пометкой plugin source).
   495→   495→
   496→   496→### Рекомендации по ролям
   497→   497→
   498→   498→Практичная настройка обычно начинается с 3-5 ролей:
   499→   499→- Code review
   500→   500→- Test debugging
   501→   501→- Documentation cleanup
   502→   502→- UI checking
   503→   503→- Release notes
   504→   504→
   505→   505→Каждая роль должна быть узкой с чётким триггером.
   506→   506→

   509→   509→## 11. Plugin — расширение возможностей
   510→   510→
   511→   511→> **Источник:** [ZCode Docs — Plugin](https://zcode.z.ai/en/newdocs/plugin)
   512→   512→
   513→   513→### Что содержит плагин
   514→   514→
   515→   515→Один плагин может объединять несколько компонентов:
   516→   516→
   517→   517→| Компонент | Описание |
   518→   518→|---|---|
   519→   519→| **Skill** | Файлы навыков, обучающие Agent определённым способам работы |
   520→   520→| **Command** | Быстрые команды, вызываемые через `/` |
   521→   521→| **Agent** | Подагенты, зарегистрированные вместе с плагином |
   522→   522→| **MCP servers** | Внешние инструментальные серверы, показанные в группе Plugin MCP |
   523→   523→| **Hook** | Автоматизационные хуки, срабатывающие на определённых событиях |
   524→   524→| **LSP** | Языковые серверы для автодополнения, диагностики и т.д. |
   525→   525→
   526→   526→При включении плагина все его компоненты регистрируются в текущем workspace; при выключении — отключаются вместе.
   527→   527→
   528→   528→### Встроенные плагины
   529→   529→
   530→   530→ZCode поставляется с набором официальных плагинов:
   531→   531→
   532→   532→| Плагин | Возможности | Компоненты |
   533→   533→|---|---|---|
   534→   534→| **android-emulator** | Android-разработка и автоматизация эмулятора | 1 skill, 1 command, 1 MCP |
   535→   535→| **ios-simulator** | iOS-разработка и автоматизация симулятора | 1 skill, 1 command, 1 MCP |
   536→   536→
   537→   537→После включения Agent может управлять Android-эмулятором или iOS-симулятором напрямую: сборка, запуск, установка, верификация UI — всё в одном разговоре.
   538→   538→
   539→   539→### Управление плагинами
   540→   540→
   541→   541→**Settings -> Plugins:**
   542→   542→- Фильтрация по имени/описанию
   543→   543→- Проверка источника (Official и т.д.)
   544→   544→- Включение/выключение переключателем
   545→   545→- Клик по плагину для просмотра его компонентов
   546→   546→- Перед выключением ZCode покажет, какие навыки, команды или MCP-серверы будут затронуты
   547→   547→
   548→   548→**Важно:** изменения плагинов требуют перезагрузки Agent runtime. Текущая сессия перезагрузится автоматически после включения/выключения плагина.
   549→   549→
   550→   550→---

   552→   552→## 12. MCP-серверы — подключение внешних инструментов
   553→   553→
   554→   554→> **Источник:** [ZCode Docs — Plugin](https://zcode.z.ai/en/newdocs/plugin) (раздел MCP servers) + [Z.AI Best Practices — Extend Agent Context with MCP](https://docs.z.ai/devpack/resources/best-practice)
   555→   555→
   556→   556→### Что это
   557→   557→
   558→   558→MCP (Model Context Protocol) — стандартный способ подключения внешних инструментов и систем, чтобы Agent мог получать информацию из-за пределов репозитория:
   559→   559→
   560→   560→- Платформы хостинга кода и коллаборации
   561→   561→- Базы данных и интерфейсы запросов
   562→   562→- API-сервисы и техническая документация
   563→   563→- Внутренние инструменты и системы автоматизации
   564→   564→
   565→   565→### Как подключить
   566→   566→
   567→   567→1. Откройте **Settings -> MCP Servers**
   568→   568→2. Добавьте конфигурацию MCP-сервера
   569→   569→3. Agent получит доступ к новым инструментам
   570→   570→
   571→   571→MCP-серверы также могут предоставляться через плагины (см. раздел Plugin).
   572→   572→

   575→   575→## 13. Edit History — редактирование отправленных сообщений
   576→   576→
   577→   577→> **Источник:** [ZCode Docs — Edit History](https://zcode.z.ai/en/newdocs/edit-history)
   578→   578→
   579→   579→### Что это
   580→   580→
   581→   581→Edit History позволяет исправлять сообщения, уже отправленные Agent. Если инструкция неясна, отсутствует путь к файлу, не хватает ограничения или нужно изменить направление — можно отредактировать исходное сообщение, и Agent продолжит с обновлённым контекстом вместо перезапуска.
   582→   582→
   583→   583→**Особенно полезно для длинных задач:** сохраняется та же модель, workspace, ветка и контекст задачи — корректируется только ключевая инструкция.
   584→   584→
   585→   585→### Как использовать
   586→   586→
   587→   587→1. В истории разговора наведите курсор на своё сообщение
   588→   588→2. Справа от сообщения появится область быстрых действий
   589→   589→3. Нажмите **иконку карандаша** (Edit)
   590→   590→4. Исходное сообщение станет редактируемым
   591→   591→5. Перепишите текст, используйте `@` для ссылок на файлы, `/` для команд
   592→   592→6. Нажмите **Send** — Agent продолжит с обновлённой инструкцией
   593→   593→7. Или **Cancel** — исходное сообщение останется без изменений
   594→   594→
   595→   595→### Правила
   596→   596→
   597→   597→- Редактировать можно только **пользовательские сообщения**, не ответы Agent
   598→   598→- Доступно только для **последнего хода** разговора
   599→   599→- Недоступно, пока задача выполняется или есть сообщения в очереди
   600→   600→
   601→   601→### Типичные сценарии
   602→   602→
   603→   603→| Сценарий | Пример |
   604→   604→|---|---|
   605→   605→| Исправить требование | Исправить ранее отправленную инструкцию, которая была неверной или неполной |
   606→   606→| Добавить контекст | Добавить путь к файлу, лог ошибки, скриншот, параметр API, ограничение |
   607→   607→| Изменить направление | Переключиться с «проанализируй» на «исправь», или с «реализуй» на «сначала спланируй» |
   608→   608→| Избежать повторной настройки | Сохранить существующий контекст задачи вместо объяснения фона заново |
   609→   609→
   610→   610→---

   612→   612→## 14. Remote Control — управление с телефона
   613→   613→
   614→   614→> **Источник:** [ZCode Docs — Remote Control](https://zcode.z.ai/en/newdocs/remote-control)
   615→   615→
   616→   616→### Когда использовать
   617→   617→
   618→   618→- Десктопная задача уже выполняется, а вам нужно отойти
   619→   619→- Получили быстрое обновление и хотите добавить инструкцию с телефона
   620→   620→- Длинная задача работает, и вы хотите проверить статус без возвращения к компьютеру
   621→   621→
   622→   622→### Как подключиться
   623→   623→
   624→   624→1. Кликните **иконку телефона** в левом нижнем углу ZCode
   625→   625→2. Появится диалог с **QR-кодом** и ссылкой для текущего workspace
   626→   626→3. Отсканируйте QR-код телефоном или откройте ссылку в мобильном браузере
   627→   627→4. Телефон подключается к текущему десктопному workspace
   628→   628→
   629→   629→**Важно:** десктоп остаётся средой выполнения; телефон используется для чтения сессии, отправки сообщений и запуска действий.
   630→   630→
   631→   631→### Что можно делать
   632→   632→
   633→   633→- Читать последний ответ Agent и прогресс задачи
   634→   634→- Отправлять новую инструкцию или дополнительный контекст
   635→   635→- Подтверждать, продолжать или останавливать длинную задачу
   636→   636→- Вернуться в текущий workspace из любого места
   637→   637→
   638→   638→**Ограничение:** только один телефон может быть подключён одновременно, и он имеет доступ только к workspace, уже открытым на десктопе.

   964→   964→
   965→   965→При возникновении неполадок сначала запустите `coding-helper doctor` для диагностики.
   966→   966→
   967→   967→**1. Сетевая ошибка (Network Error)**
   968→   968→
   969→   969→- **Проблема:** При сохранении или валидации API KEY появляются ошибки сети.

   972→   972→
   973→   973→```bash
   974→   974→export HTTP_PROXY=http://your.proxy.server:port
   975→   975→export HTTPS_PROXY=http://your.proxy.server:port
   976→   976→```

  1050→  1050→## 23. Лучшие практики работы с Coding Agent
  1051→  1051→
  1052→  1052→> **Источник:** [Z.AI Developer Docs — Best Practices for Coding Agents](https://docs.z.ai/devpack/resources/best-practice)
  1053→  1053→
  1054→  1054→Основано на официальных рекомендациях Z.AI.
  1055→  1055→
  1056→  1056→### Практика 1: Относитесь к Coding Agent как к коллаборатору, а не к одноразовому помощнику
  1057→  1057→
  1058→  1058→Распространённая ошибка — использовать Agent как инструмент «вопрос-ответ»: задал вопрос, получил код, закончил. На практике ценность Coding Agent складывается не только из возможностей модели, но и из **рабочего процесса вокруг неё**. Через файлы конфигурации проекта, интеграции инструментов и переиспользуемые навыки вы постоянно формируете поведение Agent, чтобы оно соответствовало рабочему процессу вашей команды.
  1059→  1059→
  1060→  1060→### Практика 2: Контекст важнее трюков с промптами
  1061→  1061→
  1062→  1062→В сложном проекте эффективное описание задачи включает четыре элемента: Goal, Context, Constraints, Done when. Структурированный ввод задачи снижает ненужные догадки и делает изменения Agent более согласованными и удобными для проверки.
  1063→  1063→
  1064→  1064→### Практика 3: Планируйте перед выполнением сложных задач
  1065→  1065→
  1066→  1066→Для сложных запросов Agent наиболее эффективен, когда сначала планирует, а потом действует. Используйте Goal Mode или явно просите Agent: «Сначала составь план, затем реализуй». Это снижает логические ошибки, ненужные переделки и повторные ревизии.
  1067→  1067→
  1068→  1068→### Практика 4: Сохраняйте повторяющиеся правила в файлах конфигурации проекта
  1069→  1069→
  1070→  1070→Многие промпты повторяют одни и те же правила: структура директорий, команды сборки, workflow тестирования, стандарты кода, процесс подачи PR. Если эти правила повторять в каждом промпте — это неэффективно и ведёт к дрифту инструкций. Перенесите их в файлы конфигурации проекта (Skills, Commands).
  1071→  1071→
  1072→  1072→**Простое правило:** временные инструкции — в промпте, долговременные правила — в файлах конфигурации проекта.
  1073→  1073→
  1074→  1074→### Практика 5: Среда выполнения определяет, что может Agent
  1075→  1075→
  1076→  1076→Многие проблемы, которые разработчики относят к возможностям модели, на самом деле вызваны неполной или плохо настроенной средой выполнения. Убедитесь, что:
  1077→  1077→- Рабочая директория проекта доступна
  1078→  1078→- Права на чтение/запись файлов настроены
  1079→  1079→- Команды сборки и тестирования работают
  1080→  1080→- Внешние инструменты и сервисы доступны
  1081→  1081→
  1082→  1082→### Практика 6: Вовлекайте Agent в полный цикл разработки
  1083→  1083→
  1084→  1084→Agent должен не только генерировать код, но и участвовать в полном цикле: реализация -> написание тестов -> запуск тестов -> проверки кода -> ревью изменений. В этом рабочем процессе Agent становится активным участником реализации, валидации и ревью.
  1085→  1085→
  1086→  1086→### Практика 7: Расширяйте контекст Agent через MCP
  1087→  1087→
  1088→  1088→Информация, нужная Agent, не всегда живёт внутри репозитория: таск-трекеры, CI/CD, схемы БД, API-документация. MCP позволяет Agent получать контекст напрямую из подключённых инструментов, расширяя его от «репозиторного исполнителя» до «коллаборативного узла в реальной инженерной среде».
  1089→  1089→
  1090→  1090→### Практика 8: Сохраняйте повторяющиеся рабочие процессы как Skills
  1091→  1091→
  1092→  1092→Если промпт-паттерн или поток задач используется повторно — превратите его в Skill. Это смещает использование Agent от разовых разговоров к workflow-ориентированному выполнению. По мере роста библиотеки навыков поведение Agent становится более согласованным и предсказуемым.
  1093→  1093→
  1094→  1094→### Практика 9: Автоматизируйте стабильные рабочие процессы
  1095→  1095→
  1096→  1096→Когда Skill работает надёжно — настройте автоматизацию: по расписанию или по триггеру. Например: генерация release notes при публикации, автоматическое исследование упавших CI-запусков, сканирование на баги, ежедневные отчёты.
  1097→  1097→
  1098→  1098→### Практика 10: Управляйте сессиями Agent осознанно
  1099→  1099→
  1100→  1100→Сессия — это не просто история чата, а **рабочий контекст**, накапливающий контекст, промежуточные рассуждения и результаты выполнения. Правила:
  1101→  1101→- **Отдельная сессия для каждой задачи** — не смешивайте несвязанные задачи
  1102→  1102→- **Избегайте слишком длинных сессий** — используйте `/compact` для сжатия контекста
  1103→  1103→- **Новая сессия для ответвлений** — новые направления исследования — в отдельной сессии
  1104→  1104→- **Периодически сжимайте исторический контекст** — суммаризируйте старые части разговора
  1105→  1105→

  1108→  1108→## 24. Решение частых проблем
  1109→  1109→
  1110→  1110→> **Источник:** синтез из [ZCode Docs — Feedback & Support](https://zcode.z.ai/en/newdocs/feedback) + [Z.AI Best Practices](https://docs.z.ai/devpack/resources/best-practice) + [ZCode Changelog](https://zcode.z.ai/en/changelog)
  1111→  1111→
  1112→  1112→### Agent не реагирует / зависает
  1113→  1113→
  1114→  1114→1. Проверьте подключение к модели: Settings -> Model Settings
  1115→  1115→2. Проверьте квоту: Usage Stats -> Coding Plan
  1116→  1116→3. Попробуйте перезапустить задачу: Ctrl+N -> New Task
  1117→  1117→4. Используйте `/compact` для сжатия контекста
  1118→  1118→
  1119→  1119→### Модель не отвечает / ошибки API
  1120→  1120→
  1121→  1121→1. Проверьте правильность API-ключа
  1122→  1122→2. Убедитесь, что Base URL указан корректно
  1123→  1123→3. Проверьте баланс/квоту на платформе провайдера
  1124→  1124→4. При ошибке rate limit — подождите и повторите
  1125→  1125→
  1126→  1126→### Agent теряет контекст в длинных задачах
  1127→  1127→
  1128→  1128→1. Используйте `/compact` для сжатия контекста
  1129→  1129→2. Используйте Goal Mode для автоматических итераций
  1130→  1130→3. Не смешивайте разные задачи в одной сессии
  1131→  1131→4. При необходимости начните новую задачу с кратким описанием предыдущего прогресса
  1132→  1132→
  1133→  1133→### Квота закончилась посреди задачи
  1134→  1134→
  1135→  1135→1. Проверьте текущий баланс: Usage Stats -> Coding Plan
  1136→  1136→2. Переключитесь на другую модель/провайдер
  1137→  1137→3. Подпишитесь на план или пополните баланс
  1138→  1138→4. Задача сохранится — можно продолжить после пополнения
  1139→  1139→
  1140→  1140→### Изменения не отображаются в файле
  1141→  1141→
  1142→  1142→1. Проверьте, что Agent работает с правильной директорией проекта
  1143→  1143→2. Проверьте права доступа к файлам
  1144→  1144→3. Откройте Review-панель (правая панель) для просмотра всех изменений
  1145→  1145→4. Используйте Git diff для сравнения
  1146→  1146→
  1147→  1147→### Ошибки при запуске на Windows
  1148→  1148→
  1149→  1149→1. Убедитесь, что установщик запущен с правами администратора
  1150→  1150→2. Проверьте антивирус — он может блокировать выполнение
  1151→  1151→3. Проверьте логи: `%USERPROFILE%\.zcode\logs`
  1152→  1152→4. Отправьте отчёт через встроенную форму обратной связи
