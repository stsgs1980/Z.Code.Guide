    43→## 1. Что такое ZCode 3.0
    44→
    45→> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome)
    46→
    47→ZCode — это **Agentic Development Environment (ADE)**, среда разработки, построенная вокруг AI-агента. Ключевая идея: вы описываете задачу на естественном языке, а Agent сам планирует, пишет код, тестирует и проверяет. В отличие от обычного автодополнения, Agent работает **долго и стабильно** — от постановки задачи до финальной проверки.
    48→
    49→### Две ключевые силы ZCode
    50→
    51→| Сила | Описание |
    52→|---|---|
    53→| **Длинные задачи (Long Horizon Tasks)** | Agent держит контекст от планирования до верификации — понимание требований, файлы, терминал, браузер, Git — всё в одной задаче |
    54→| **Стабильность** | Саморазработанный ZCode Agent не теряет нить выполнения даже в многочасовых задачах с сотнями шагов |
    55→
    56→### Основные возможности
    57→
    58→- **Длинные задачи**: в одном таске — понимание требований, планирование, код, верификация, Review
    59→- **Стабильный контекст**: файлы + терминал + браузер + режимы выполнения + Git — Agent ничего не забывает
    60→- **Собственный Agent-флоу**: задачи, права, контекст, вызовы инструментов и Review — всё вокруг ZCode Agent
    61→- **Мультиустройственное продолжение**: десктоп, мобильный Remote и Feishu/WeChat Bot — один и тот же таск на всех
    62→- **Безопасность**: опасные команды, изменение файлов и высокопривилегированные действия — через подтверждение
    63→- **Расширяемость**: Skills, Commands, Subagents, Plugins, MCP-серверы — настраивайте Agent под свою команду

   104→## 3. API Key Setup — подключение моделей
   105→
   106→> **Источник:** [ZCode Docs — Configuration (API Key Setup)](https://zcode.z.ai/en/newdocs/configuration)
   107→
   108→ZCode поддерживает три способа подключения AI-сервисов:
   109→
   110→| Способ | Описание |
   111→|---|---|
   112→| **BigModel** | Аккаунт Zhipu — для Китая. Поддержка GLM Coding Plan, ресурсные пакеты, предоплата |
   113→| **Z.AI** | Для международных пользователей. USD-ценообразование, бесплатная дневная квота |
   114→| **Сторонние провайдеры** | Любой сервис, совместимый с протоколами Anthropic / OpenAI |
   115→
   116→### Рекомендуемый вариант
   117→
   118→**Для международных пользователей:** подпишитесь на GLM Coding Plan через Z.AI (USD-ценообразование) — получите доступ к GLM-5.2 с бесплатной дневной пробной квотой.
   119→
   120→**Для пользователей из Китая:** подпишитесь через BigModel — те же модели, но с более выгодной ценовой политикой.
   121→
   122→### Точки входа для настройки
   123→
   124→**Способ 1: Экран приветствия при первом запуске**
   125→
   126→При первом открытии ZCode (если нет подключённых моделей) предложит:
   127→- **Continue with Z.ai** — авторизация через аккаунт Z.AI
   128→- **Continue with BigModel** — авторизация через Zhipu BigModel
   129→- **Use API key** — ввести ключ вручную и перейти к настройкам моделей
   130→
   131→После выбора Z.ai или BigModel откроется процесс авторизации. При успешной аутентификации аккаунт привязывается автоматически.
   132→
   133→**Способ 2: Селектор моделей**
   134→
   135→После входа в ZCode кликните на имя модели в поле чата → **Manage Models** внизу списка → откроется панель **Settings -> Model Settings**.
   136→
   137→### Подключение BigModel
   138→
   139→1. Откройте панель Model Settings
   140→2. Выберите **BigModel** из списка провайдеров слева
   141→3. Подключите аккаунт и включите переключатель
   142→4. Используйте переключатель в правом верхнем углу для выбора режима: **Coding Plan** или **API Key**
   143→
   144→**Бесплатная пробная квота:** новые пользователи получают trial-план сразу при подключении BigModel — без оплаты, с бесплатной дневной квотой для флагманских GLM-моделей. Страница провайдера показывает текущий баланс и использование в реальном времени.
   145→
   146→**Подписка на Coding Plan внутри ZCode:** на странице BigModel доступны планы GLM Coding (Lite / Pro / Max) с ежемесячной, квартальной и годовой оплатой. Можно завершить покупку прямо в приложении.
   147→
   148→**Подключение через API Key:**
   149→1. Переключите режим подключения на **API Key**
   150→2. Base URL по умолчанию: `https://open.bigmodel.cn/api/anthropic`
   151→3. Введите API-ключ с платформы Zhipu
   152→4. Модели по умолчанию: GLM-5.2, GLM-5-Turbo, GLM-5V-Turbo
   153→5. Нажмите **Add Model** для добавления других моделей
   154→
   155→### Подключение Z.AI
   156→
   157→Z.AI — вариант для международных пользователей. Настройка аналогична BigModel:
   158→1. Откройте панель Model Settings
   159→2. Выберите **Z.ai** из списка провайдеров
   160→3. Подключите аккаунт и включите переключатель
   161→4. Переключатель Coding Plan / API Key в правом верхнем углу
   162→
   163→Base URL для API Key: `https://api.z.ai/api/anthropic`
   164→
   165→### Подключение сторонних провайдеров
   166→
   167→| Провайдер | Base URL | Модели |
   168→|---|---|---|
   169→| **Anthropic (Claude)** | `https://api.anthropic.com` | claude-fable-5, claude-opus-4-8, claude-sonnet-4-6, claude-haiku-4-5 |
   170→| **OpenRouter** | `https://openrouter.ai/api` | Любые модели OpenRouter |
   171→| **Moonshot** | `https://api.moonshot.cn/anthropic` | kimi-k2.6 и другие |
   172→| **OpenAI** | `https://api.openai.com` | gpt-5.5, gpt-5.5-pro, gpt-5.4-mini |
   173→| **MiniMax** | `https://api.minimaxi.com/anthropic` | MiniMax-M3, MiniMax-M2.5 |

   178→**Порядок подключения любого провайдера:**
   179→1. Откройте Model Settings
   180→2. Нажмите **Add Provider** внизу списка слева
   181→3. Введите имя провайдера
   182→4. Выберите vendor Base URL из выпадающего списка или введите вручную
   183→5. Введите API-ключ
   184→6. Система автоматически загрузит список доступных моделей
   185→7. Включите переключатель — готово
   186→
   187→### Проверка настройки
   188→
   189→Выберите канал из селектора моделей в чате и отправьте короткую тестовую инструкцию. Если модель отвечает стабильно — настройка завершена.

   193→## 4. Интерфейс — что где находится
   194→
   195→> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome) + [ZCode Homepage](https://zcode.z.ai)
   196→
   197→### Рабочее пространство (Workspace)
   198→
   199→```
   200→+-------------------------------------------------------------+
   201→|  Модель: GLM-5.2 | Max | Thought Level | Настройки чата     |
   202→+----------+----------------------------+---------------------+
   203→|          |                            |                     |
   204→|  Файлы   |      Чат с Agent          |  Git tools          |
   205→|  +       |                            |  + Goal             |
   206→|  Задачи  |  Agent: «Создаю API...»   |                     |
   207→|  по      |                            |  Changes:           |
   208→|  датам   |  [файл] [терминал]        |  +734 -7            |
   209→|          |                            |  Commit             |
   210→|          |                            |                     |
   211→+----------+----------------------------+---------------------+
   212→|  Терминал (zsh / bash)                                      |
   213→|  user@project % _                                           |
   214→+-------------------------------------------------------------+
   215→```
   216→
   217→### Элементы интерфейса
   218→
   219→| Элемент | Расположение | Что делает |
   220→|---|---|---|
   221→| **Боковая панель (левая)** | Слева | Дерево файлов + таймлайн задач, сгруппированных по дате |
   222→| **Центральная область** | Центр | Чат с Agent + просмотр/редактирование кода |
   223→| **Нижняя панель** | Внизу | Терминал (zsh/bash) |
   224→| **Правая панель** | Справа | Git-инструменты (ветки, коммиты) + Goal (цели) + Changes (изменения) |
   225→| **Верхняя строка чата** | Верх | Выбор модели, режим рассуждений, режим стриминга |
   226→| **Иконка телефона** | Левый нижний угол | Mobile Remote Control (QR-код для подключения) |
   227→| **Аватар** | Левый нижний угол | Меню: Feedback, настройки и т.д. |
   228→| **Поле ввода чата** | Внизу центра | Ввод инструкций, `/` команды, `$` навыки, `@` подагенты |

   232→## 5. Работа с ZCode Agent — базовый рабочий процесс
   233→
   234→> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome) + [Z.AI Best Practices](https://docs.z.ai/devpack/resources/best-practice)
   235→
   236→### Простая задача
   237→
   238→1. Откройте чат: **Cmd+N** (Mac) / **Ctrl+N** (Win) → «New Task»
   239→2. Напишите инструкцию на естественном языке
   240→3. Agent автоматически: исследует проект, создаст файлы, напишет код, запустит проверки
   241→4. Следите за прогрессом в реальном времени
   242→
   243→### Что делает Agent в процессе
   244→
   245→| Шаг | Что происходит |
   246→|---|---|
   247→| **Exploring** | Agent исследует проект: ищет файлы, читает структуру |
   248→| **Planning** | Составляет план: какие файлы создать/изменить |
   249→| **Writing** | Пишет код, создаёт файлы |
   250→| **Running** | Выполняет команды в терминале (npm install, npm test и т.д.) |
   251→| **Verifying** | Проверяет результат: запускает тесты, линтер |
   252→| **Reviewing** | Показывает финальные изменения: +N строк, -M строк |
   253→
   254→### Как давать инструкции Agent — 4 элемента эффективного промпта
   255→
   256→В сложном проекте эффективное описание задачи обычно включает четыре элемента:
   257→
   258→| Элемент | Описание | Пример |
   259→|---|---|---|
   260→| **Goal** | Что нужно построить или изменить | «Исправь баг авторизации» |
   261→| **Context** | Релевантные файлы, ошибки, документация | «Файл auth.ts, строка 42, ошибка E401» |
   262→| **Constraints** | Ограничения: стандарты, архитектура, зависимости | «Используй JWT, не меняй схему БД» |
   263→| **Done when** | Критерий завершения | «Тесты auth.test.ts проходят» |
   264→
   265→**Хорошо:** «Исправь баг авторизации в auth.ts (строка 42, ошибка E401). Используй JWT, не меняй схему БД. Готово, когда auth.test.ts проходит.»
   266→
   267→**Плохо:** «Почини авторизацию»

   271→## 6. Режимы выполнения (Execution Modes)
   272→
   273→> **Источник:** [ZCode Docs — Goal Mode](https://zcode.z.ai/en/newdocs/goal) (раздел «Combine with execution modes»)
   274→
   275→ZCode Agent поддерживает несколько режимов выполнения, которые определяют, сколько действий требуют подтверждения:
   276→
   277→| Режим | Описание | Когда использовать |
   278→|---|---|---|
   279→| **Full Access / Auto Edit** | Agent выполняет действия без постоянных подтверждений | Для длинных задач, Goal Mode — минимум прерываний |
   280→| **По умолчанию** | Опасные действия требуют подтверждения | Для повседневной разработки |
   281→| **Strict / Manual** | Каждое действие требует подтверждения | Для критических изменений |
   282→
   283→**Как переключить:** нажмите **Shift+Tab** (когда фокус в поле ввода чата) для циклического переключения режимов.
   284→
   285→**Совет:** Для длинных goal-driven задач комбинируйте Goal Mode с Full Access — это минимизирует прерывания и позволяет итерациям идти непрерывно.

   289→## 7. Goal Mode — режим целей для сложных задач
   290→
   291→> **Источник:** [ZCode Docs — Goal Mode](https://zcode.z.ai/en/newdocs/goal)
   292→
   293→### Когда использовать
   294→
   295→- Задача легко описывается одним предложением, но требует много итераций
   296→- Примеры: «Отрефактори весь модуль, чтобы тесты проходили», «Исправь все TypeScript-ошибки», «Получи Lighthouse-оценку выше 90»
   297→
   298→### Как работает
   299→
   300→1. Вы ставите цель через `/goal`
   301→2. Agent работает итеративно — в конце каждой итерации **автоматически проверяет** цель
   302→3. Если цель не достигнута — начинается следующая итерация
   303→4. Задача завершается только когда цель **верифицирована как выполненная**
   304→5. Вам не нужно повторно писать «продолжай» — Agent продолжает сам
   305→
   306→### Команды Goal Mode
   307→
   308→| Команда | Описание |
   309→|---|---|
   310→| `/goal <objective>` | Установить цель сессии |
   311→| `/goal replace <objective>` | Заменить текущую цель |
   312→| `/goal pause` | Поставить цель на паузу |
   313→| `/goal resume` | Возобновить цель |
   314→| `/goal clear` | Удалить цель |
   315→
   316→### Совет по формулировке цели
   317→
   318→Делайте цель **конкретной и проверяемой**:  
   319→«Исправь все TypeScript-ошибки компиляции и добейся, чтобы `pnpm test` проходил» — лучше, чем «исправь ошибки».
   320→
   321→### Что происходит после установки цели
   322→
   323→1. **Карточка цели** появляется в панели сводки (правый верхний угол) — статус (active/paused/complete), затраченное время, токены, количество итераций
   324→2. **Автоматическая верификация** после каждой итерации
   325→3. **Можно вмешаться в любой момент**: заменить цель, поставить на паузу, очистить
   326→

   329→## 8. Command — встроенные и пользовательские команды
   330→
   331→> **Источник:** [ZCode Docs — Command](https://zcode.z.ai/en/newdocs/commands)
   332→
   333→### Встроенные команды
   334→
   335→| Команда | Назначение |
   336→|---|---|
   337→| `/goal` | Показать, установить, заменить, приостановить, возобновить или очистить цель текущей сессии |
   338→| `/compact` | Сжать контекст текущего разговора с сохранением ключевой информации — полезно для продолжения длинных бесед |
   339→
   340→### Как использовать
   341→
   342→Введите `/` в поле ввода — откроется панель команд, организованная по группам **Commands** и **Skills**. Продолжайте печатать для фильтрации.
   343→
   344→### Создание пользовательской команды
   345→
   346→1. Откройте **Settings -> Commands**
   347→2. Нажмите **Create new command**
   348→3. Заполните поля:
   349→
   350→| Поле | Описание |
   351→|---|---|
   352→| **Scope** | User (доступно во всех workspace) или Workspace (только текущий проект) |
   353→| **Name** | Имя команды, вызывается как `/command-name` |
   354→| **Description** | Краткое описание, отображается в пикере команд |
   355→| **Argument hint** | Подсказка параметра, например `<file-path>` |
   356→| **Prompt** | Содержимое промпта, отправляемое Agent при запуске команды |
   357→
   358→Команды хранятся как `.md`-файлы в `~/.zcode/commands/` (на уровне пользователя) или в директории проекта (на уровне workspace).
   359→
   360→### Импорт команд из внешних Agent
   361→
   362→Если у вас есть команды в Claude Code или другом Agent — не нужно создавать их заново:
   363→1. Откройте **Commands** в настройках ZCode
   364→2. Нажмите **Import commands from external Agent** в правом верхнем углу
   365→3. Выберите нужные команды и подтвердите
   366→
   367→### Когда использовать Command vs Skill
   368→
   369→- **Command** — для простого сохранённого промпта
   370→- **Skill** — когда нужен полный рабочий метод с шаблонами, чеклистами, примерами
   371→

   374→## 9. Skill — переиспользуемые рабочие инструкции
   375→
   376→> **Источник:** [ZCode Docs — Skill](https://zcode.z.ai/en/newdocs/skill)
   377→
   378→### Что это
   379→
   380→Skill — это переиспользуемая рабочая инструкция, определяемая файлом `SKILL.md`. Описывает, когда навык используется, как Agent должен работать и какой результат ожидается.
   381→
   382→### Управление навыками
   383→
   384→Откройте **Settings -> Skills** — каждая строка показывает имя навыка, источник, описание и переключатель включения.
   385→
   386→- Поиск навыков по имени
   387→- Включение/выключение переключателем
   388→- **New Skill** в правом верхнем углу — Agent поможет создать навык прямо в чате
   389→
   390→### Создание навыка
   391→
   392→Навык — это директория с файлом `SKILL.md` внутри:
   393→
   394→```
   395→~/.zcode/skills/<skill-name>/SKILL.md
   396→```
   397→
   398→Минимальный `SKILL.md`:
   399→
   400→```markdown
   401→---
   402→name: code-review-checklist
   403→description: Review code changes with a focused checklist for correctness, regressions, tests, and maintainability.
   404→---
   405→
   406→# Code Review Checklist
   407→
   408→Use this skill when reviewing a pull request, merge request, or local diff.
   409→
   410→Focus on correctness, regressions, missing tests, risky API changes, and maintainability.
   411→```
   412→
   413→После создания: **Settings -> Skills -> Refresh** — навык появится в списке.
   414→
   415→### Импорт навыков из внешних Agent
   416→
   417→Поддерживается импорт из Claude Code, Codex CLI, OpenClaw, Augment, Windsurf:
   418→
   419→1. **Settings -> Skills** -> нажмите иконку **Import** в правом верхнем углу
   420→2. ZCode просканирует директории внешних Agent и покажет доступные навыки
   421→3. Выберите навыки и режим импорта:
   422→   - **Symlink** — связь с внешней директорией (изменения синхронизируются, но зависит от пути)
   423→   - **Copy** — независимая копия (без синхронизации с источником)
   424→4. Выберите цель импорта: **Global** (на уровне пользователя) или **Project** (текущий workspace)
   425→
   426→### Использование навыка в чате
   427→
   428→Введите `$` в поле ввода и выберите навык. Навык появится как тег, после которого можно продолжить запрос:
   429→
   430→```
   431→$code-review-checklist review my current changes
   432→$release-notes write release notes for this change set
   433→```
   434→
   435→### Что стоит сделать навыком
   436→
   437→- Задача повторяется: code review, API debugging, release notes, test reports
   438→- Команда ожидает единообразный формат вывода
   439→- Рабочий процесс требует фоновых знаний, чеклистов, шаблонов или примеров
   440→- Возможность будет переиспользована в разных проектах
   441→

   444→## 10. Subagents — подагенты для делегирования задач
   445→
   446→> **Источник:** [ZCode Docs — Subagents](https://zcode.z.ai/en/newdocs/subagents)
   447→
   448→### Что это
   449→
   450→Subagents — специализированные роли, подготовленные для Agent. Вы можете превратить повторяющиеся задачи (code review, отладка тестов, release notes, проверка UI) в подагенты, чтобы активный Agent мог делегировать им целенаправленную работу.
   451→
   452→### Использование в чате
   453→
   454→Введите `@` в поле ввода и выберите роль из группы **Agents**:
   455→
   456→```
   457→@zcode-reviewer проверь текущие изменения на риск регрессии
   458→@zcode-test-helper найди, почему этот тест падает
   459→```
   460→
   461→### Настройка подагентов
   462→
   463→Подагенты определяются как Markdown-файлы:
   464→
   465→- **На уровне пользователя** (доступны во всех workspace): `~/.zcode/cli/agents/`
   466→- **На уровне workspace** (только текущий проект): `<workspace>/.zcode/cli/agents/`
   467→
   468→Каждый подагент — `.md`-файл с опциональным YAML frontmatter + системный промпт:
   469→
   470→```markdown
   471→---
   472→name: zcode-reviewer
   473→description: Check changes for regression risk before committing
   474→color: "#3b82f6"
   475→model: glm-5.2
   476→tools: Read, Grep, Bash
   477→---
   478→
   479→You are a code-review subagent focused on regression risk, edge cases, and test coverage…
   480→```
   481→
   482→**Поля frontmatter:**
   483→
   484→| Поле | Описание |
   485→|---|---|
   486→| `name` | 3-50 символов, буквы, цифры и дефисы |
   487→| `description` | Когда использовать — управляет автоматическим делегированием |
   488→| `color` (опционально) | Акцентный цвет в UI, например `#3b82f6` |
   489→| `model` (опционально) | Конкретная модель; пусто = текущая модель сессии |
   490→| `tools` (опционально) | Ограничение доступных инструментов |
   491→
   492→### Подагенты из плагинов
   493→
   494→Подагенты также могут предоставляться плагинами. После включения плагина роли появляются в списке автоматически (с пометкой plugin source).
   495→
   496→### Рекомендации по ролям
   497→
   498→Практичная настройка обычно начинается с 3-5 ролей:
   499→- Code review
   500→- Test debugging
   501→- Documentation cleanup
   502→- UI checking
   503→- Release notes
   504→
   505→Каждая роль должна быть узкой с чётким триггером.
   506→

   509→## 11. Plugin — расширение возможностей
   510→
   511→> **Источник:** [ZCode Docs — Plugin](https://zcode.z.ai/en/newdocs/plugin)
   512→
   513→### Что содержит плагин
   514→
   515→Один плагин может объединять несколько компонентов:
   516→
   517→| Компонент | Описание |
   518→|---|---|
   519→| **Skill** | Файлы навыков, обучающие Agent определённым способам работы |
   520→| **Command** | Быстрые команды, вызываемые через `/` |
   521→| **Agent** | Подагенты, зарегистрированные вместе с плагином |
   522→| **MCP servers** | Внешние инструментальные серверы, показанные в группе Plugin MCP |
   523→| **Hook** | Автоматизационные хуки, срабатывающие на определённых событиях |
   524→| **LSP** | Языковые серверы для автодополнения, диагностики и т.д. |
   525→
   526→При включении плагина все его компоненты регистрируются в текущем workspace; при выключении — отключаются вместе.
   527→
   528→### Встроенные плагины
   529→
   530→ZCode поставляется с набором официальных плагинов:
   531→
   532→| Плагин | Возможности | Компоненты |
   533→|---|---|---|
   534→| **android-emulator** | Android-разработка и автоматизация эмулятора | 1 skill, 1 command, 1 MCP |
   535→| **ios-simulator** | iOS-разработка и автоматизация симулятора | 1 skill, 1 command, 1 MCP |
   536→
   537→После включения Agent может управлять Android-эмулятором или iOS-симулятором напрямую: сборка, запуск, установка, верификация UI — всё в одном разговоре.
   538→
   539→### Управление плагинами
   540→
   541→**Settings -> Plugins:**
   542→- Фильтрация по имени/описанию
   543→- Проверка источника (Official и т.д.)
   544→- Включение/выключение переключателем
   545→- Клик по плагину для просмотра его компонентов
   546→- Перед выключением ZCode покажет, какие навыки, команды или MCP-серверы будут затронуты
   547→
   548→**Важно:** изменения плагинов требуют перезагрузки Agent runtime. Текущая сессия перезагрузится автоматически после включения/выключения плагина.
   549→

   552→## 12. MCP-серверы — подключение внешних инструментов
   553→
   554→> **Источник:** [ZCode Docs — Plugin](https://zcode.z.ai/en/newdocs/plugin) (раздел MCP servers) + [Z.AI Best Practices — Extend Agent Context with MCP](https://docs.z.ai/devpack/resources/best-practice)
   555→
   556→### Что это
   557→
   558→MCP (Model Context Protocol) — стандартный способ подключения внешних инструментов и систем, чтобы Agent мог получать информацию из-за пределов репозитория:
   559→
   560→- Платформы хостинга кода и коллаборации
   561→- Базы данных и интерфейсы запросов
   562→- API-сервисы и техническая документация
   563→- Внутренние инструменты и системы автоматизации
   564→
   565→### Как подключить
   566→
   567→1. Откройте **Settings -> MCP Servers**
   568→2. Добавьте конфигурацию MCP-сервера
   569→3. Agent получит доступ к новым инструментам
   570→
   571→MCP-серверы также могут предоставляться через плагины (см. раздел Plugin).

   575→## 13. Edit History — редактирование отправленных сообщений
   576→
   577→> **Источник:** [ZCode Docs — Edit History](https://zcode.z.ai/en/newdocs/edit-history)
   578→
   579→### Что это
   580→
   581→Edit History позволяет исправлять сообщения, уже отправленные Agent. Если инструкция неясна, отсутствует путь к файлу, не хватает ограничения или нужно изменить направление — можно отредактировать исходное сообщение, и Agent продолжит с обновлённым контекстом вместо перезапуска.
   582→
   583→**Особенно полезно для длинных задач:** сохраняется та же модель, workspace, ветка и контекст задачи — корректируется только ключевая инструкция.
   584→
   585→### Как использовать
   586→
   587→1. В истории разговора наведите курсор на своё сообщение
   588→2. Справа от сообщения появится область быстрых действий
   589→3. Нажмите **иконку карандаша** (Edit)
   590→4. Исходное сообщение станет редактируемым
   591→5. Перепишите текст, используйте `@` для ссылок на файлы, `/` для команд
   592→6. Нажмите **Send** — Agent продолжит с обновлённой инструкцией
   593→7. Или **Cancel** — исходное сообщение останется без изменений
   594→
   595→### Правила
   596→
   597→- Редактировать можно только **пользовательские сообщения**, не ответы Agent
   598→- Доступно только для **последнего хода** разговора
   599→- Недоступно, пока задача выполняется или есть сообщения в очереди
   600→
   601→### Типичные сценарии
   602→
   603→| Сценарий | Пример |
   604→|---|---|
   605→| Исправить требование | Исправить ранее отправленную инструкцию, которая была неверной или неполной |
   606→| Добавить контекст | Добавить путь к файлу, лог ошибки, скриншот, параметр API, ограничение |
   607→| Изменить направление | Переключиться с «проанализируй» на «исправь», или с «реализуй» на «сначала спланируй» |
   608→| Избежать повторной настройки | Сохранить существующий контекст задачи вместо объяснения фона заново |
   609→

   612→## 14. Remote Control — управление с телефона
   613→
   614→> **Источник:** [ZCode Docs — Remote Control](https://zcode.z.ai/en/newdocs/remote-control)
   615→
   616→### Когда использовать
   617→
   618→- Десктопная задача уже выполняется, а вам нужно отойти
   619→- Получили быстрое обновление и хотите добавить инструкцию с телефона
   620→- Длинная задача работает, и вы хотите проверить статус без возвращения к компьютеру
   621→
   622→### Как подключиться
   623→
   624→1. Кликните **иконку телефона** в левом нижнем углу ZCode
   625→2. Появится диалог с **QR-кодом** и ссылкой для текущего workspace
   626→3. Отсканируйте QR-код телефоном или откройте ссылку в мобильном браузере
   627→4. Телефон подключается к текущему десктопному workspace
   628→
   629→**Важно:** десктоп остаётся средой выполнения; телефон используется для чтения сессии, отправки сообщений и запуска действий.
   630→
   631→### Что можно делать
   632→
   633→- Читать последний ответ Agent и прогресс задачи
   634→- Отправлять новую инструкцию или дополнительный контекст
   635→- Подтверждать, продолжать или останавливать длинную задачу
   636→- Вернуться в текущий workspace из любого места
   637→
   638→**Ограничение:** только один телефон может быть подключён одновременно, и он имеет доступ только к workspace, уже открытым на десктопе.

   642→## 15. Bot Channel — Feishu / WeChat / Telegram
   643→
   644→> **Источник:** [ZCode Docs — Bot Channel](https://zcode.z.ai/en/newdocs/bot-channel)
   645→
   646→### Remote Control vs Bot Channel
   647→
   648→| Remote Control | Bot Channel |
   649→|---|---|
   650→| Быстрый доступ через QR-код | Точка входа живёт внутри чат-инструмента |
   651→| Для временного подключения | Для длительного доступа из мессенджера |
   652→| Один телефон одновременно | Можно пересматривать переписку с ботом |
   653→
   654→### Создание Bot Channel
   655→
   656→1. Откройте **Bots** в левой боковой панели
   657→2. Нажмите **Create Bot**
   658→3. Выберите канал для подключения
   659→
   660→**Доступные каналы:**
   661→- **WeChat** — сканируйте для входа и автоматической привязки
   662→- **Feishu** — сканируйте для создания приложения, затем привяжите через сообщения
   663→- **Telegram** — создайте бота, затем привяжите через сообщения
   664→
   665→DingTalk, Discord и WeCom будут добавлены в будущих версиях.
   666→
   667→### Привязка Feishu
   668→
   669→1. Выберите Feishu в ZCode
   670→2. Отсканируйте QR-код — ZCode автоматически создаст приложение Feishu
   671→3. ZCode сгенерирует код привязки (pairing code)
   672→4. В разговоре Feishu отправьте `/bind pairing-code`
   673→5. После подтверждения бот готов к использованию
   674→
   675→После привязки Feishu-бот вернёт список доступных команд: проверка статуса, создание задач, переключение проектов, переключение моделей, изменение режима выполнения, настройка детальности ответов.
   676→
   677→### Управление ботами
   678→
   679→После создания боты появляются в списке слева. Доступные настройки:
   680→- **Bind Bot** — привязка учётных данных
   681→- **Reply granularity** — контроль детальности ответов бота
   682→- **Workspace access scope** — ограничение доступных workspace
   683→- **Delete Bot** — удаление канала

   858→## 21. Coding Tool Helper — управление CLI-инструментами
   859→
   860→> **Источник:** [Z.AI Docs — Coding Tool Helper](https://docs.z.ai/devpack/extension/coding-tool-helper)
   861→
   862→### Что это
   863→
   864→Coding Tool Helper — это консольный помощник, который помогает пользователям GLM Coding Plan централизованно управлять и настраивать CLI-инструменты разработки, такие как Claude Code, OpenCode, Crush и Factory Droid. Установите и запустите его, следуйте экранным инструкциям — и он автоматически установит инструменты, настроит план и управит MCP-серверами.
   865→
   866→**NPM-пакет:** `@z_ai/coding-helper`  
   867→**Требование:** Node.js >= v18.0.0
   868→
   869→### Поддерживаемые инструменты
   870→
   871→| Инструмент | Описание |
   872→|---|---|
   873→| **Claude Code** | CLI-агент от Anthropic |
   874→| **OpenCode** | Открытый CLI-инструмент для кодирования |
   875→| **Crush** | CLI-агент для разработки |
   876→| **Factory Droid** | Инструмент автоматизации разработки |
   877→
   878→### Ключевые возможности
   879→
   880→| Возможность | Описание |
   881→|---|---|
   882→| **Интерактивный мастер** | Пошаговая настройка с дружественным интерфейсом |
   883→| **Интеграция плана** | Подключение GLM Coding Plan к выбранному CLI-инструменту |
   884→| **Управление инструментами** | Автоматическое обнаружение, установка и конфигурация |

   889→### Быстрый старт
   890→
   891→**Шаг 1 — Получите API Key**
   892→
   893→Посетите [Z.AI Open Platform](https://z.ai) для получения API-ключа.
   894→
   895→**Шаг 2 — Установка и запуск**
   896→
   897→Требование: Node.js 18+ или новее. Два способа установки:
   898→
   899→**Метод 1 (рекомендуемый — npx без глобальной установки):**
   900→

   904→## Запуск Coding Tool Helper прямо в терминале

   909→

   911→
   912→Если `npm install` выдаёт ошибку прав, добавьте `sudo` (macOS/Linux) или запустите терминал от имени администратора (Windows). Альтернативно — используйте npx: `npx @z_ai/coding-helper`
   913→

   915→## Глобальная установка
   916→npm install -g @z_ai/coding-helper

   936→
   937→Помимо интерактивного мастера, Coding Tool Helper поддерживает запуск конкретных команд через `coding-helper` или `chelper` с аргументами:
   938→
   939→```bash
   940→# Запуск мастера инициализации
   941→coding-helper init
   942→
   943→# Управление языком
   944→coding-helper lang show              # Показать текущий язык
   945→coding-helper lang set en_US         # Переключить на английский
   946→coding-helper lang --help            # Справка по языковым командам
   947→
   948→# Управление API-ключом
   949→coding-helper auth                   # Настроить ключ интерактивно
   950→coding-helper auth glm_coding_plan_global <token>     # Выбрать Global-план и задать ключ напрямую
   951→coding-helper auth revoke            # Удалить сохранённый ключ

   953→coding-helper auth --help            # Справка по командам авторизации
   954→
   955→# Диагностика
   956→coding-helper doctor                 # Проверка конфигурации системы и статуса инструментов
   957→
   958→# Общие
   959→coding-helper --help                 # Показать справку
   960→coding-helper --version              # Показать версию
   961→```
   962→
   963→### Решение проблем
   964→
   965→При возникновении неполадок сначала запустите `coding-helper doctor` для диагностики.
   966→
   967→**1. Сетевая ошибка (Network Error)**
   968→
   969→- **Проблема:** При сохранении или валидации API KEY появляются ошибки сети.
   970→- **Решение:** Проверьте подключение к сети или настройте прокси.
   971→- **Примечание:** Node.js не использует системный прокси автоматически. Установите переменные окружения `HTTP_PROXY` и `HTTPS_PROXY`:
   972→
   973→```bash
   974→export HTTP_PROXY=http://your.proxy.server:port
   975→export HTTPS_PROXY=http://your.proxy.server:port
   976→```
   977→
   978→**2. Таймаут сети**
   979→
   980→- **Проблема:** При установке или запуске инструментов появляются ошибки таймаута.
   981→- **Решение:** Проверьте сетевое подключение или настройте прокси.
   982→
   983→**3. Недостаточно прав (EACCES: permission denied)**
   984→
   985→- **Проблема:** `npm install -g` выдаёт ошибку EACCES.
   986→- **Решение:**
   987→  - Используйте `sudo` (macOS/Linux)
   988→  - Запустите терминал от имени администратора (Windows)
   989→  - Используйте `npx @z_ai/coding-helper` вместо глобальной установки
   990→  - Используйте nvm для управления версиями Node.js и избегания проблем с правами
   991→
   992→**4. Некорректный статус плагина в Claude Code Marketplace**
   993→
   994→- **Проблема:** Статус плагина отображается некорректно (например, «не установлен», хотя уже установлен).
   995→- **Решение:** Запустите `claude update` для обновления Claude Code до версии 2.0.70 или новее.
   996→
   997→**5. Недействительный API Key**
   998→
   999→- **Проблема:** API Key помечен как недействительный.
  1000→- **Решение:**
  1001→  - Проверьте корректность скопированного ключа
  1002→  - Убедитесь, что на связанном аккаунте достаточный баланс
  1003→
  1004→**6. Таймаут подключения**
  1005→
  1006→- **Проблема:** Время подключения к сервису истекло.
  1007→- **Решение:**
  1008→  - Проверьте сетевое подключение
  1009→  - Проверьте настройки брандмауэра
  1010→  - Убедитесь, что Node.js и сетевое окружение готовы

  1050→## 23. Лучшие практики работы с Coding Agent
  1051→
  1052→> **Источник:** [Z.AI Developer Docs — Best Practices for Coding Agents](https://docs.z.ai/devpack/resources/best-practice)
  1053→
  1054→Основано на официальных рекомендациях Z.AI.
  1055→
  1056→### Практика 1: Относитесь к Coding Agent как к коллаборатору, а не к одноразовому помощнику
  1057→
  1058→Распространённая ошибка — использовать Agent как инструмент «вопрос-ответ»: задал вопрос, получил код, закончил. На практике ценность Coding Agent складывается не только из возможностей модели, но и из **рабочего процесса вокруг неё**. Через файлы конфигурации проекта, интеграции инструментов и переиспользуемые навыки вы постоянно формируете поведение Agent, чтобы оно соответствовало рабочему процессу вашей команды.
  1059→
  1060→### Практика 2: Контекст важнее трюков с промптами
  1061→
  1062→В сложном проекте эффективное описание задачи включает четыре элемента: Goal, Context, Constraints, Done when. Структурированный ввод задачи снижает ненужные догадки и делает изменения Agent более согласованными и удобными для проверки.
  1063→
  1064→### Практика 3: Планируйте перед выполнением сложных задач
  1065→
  1066→Для сложных запросов Agent наиболее эффективен, когда сначала планирует, а потом действует. Используйте Goal Mode или явно просите Agent: «Сначала составь план, затем реализуй». Это снижает логические ошибки, ненужные переделки и повторные ревизии.
  1067→
  1068→### Практика 4: Сохраняйте повторяющиеся правила в файлах конфигурации проекта
  1069→
  1070→Многие промпты повторяют одни и те же правила: структура директорий, команды сборки, workflow тестирования, стандарты кода, процесс подачи PR. Если эти правила повторять в каждом промпте — это неэффективно и ведёт к дрифту инструкций. Перенесите их в файлы конфигурации проекта (Skills, Commands).
  1071→
  1072→**Простое правило:** временные инструкции — в промпте, долговременные правила — в файлах конфигурации проекта.
  1073→
  1074→### Практика 5: Среда выполнения определяет, что может Agent
  1075→
  1076→Многие проблемы, которые разработчики относят к возможностям модели, на самом деле вызваны неполной или плохо настроенной средой выполнения. Убедитесь, что:
  1077→- Рабочая директория проекта доступна
  1078→- Права на чтение/запись файлов настроены
  1079→- Команды сборки и тестирования работают
  1080→- Внешние инструменты и сервисы доступны
  1081→
  1082→### Практика 6: Вовлекайте Agent в полный цикл разработки
  1083→
  1084→Agent должен не только генерировать код, но и участвовать в полном цикле: реализация -> написание тестов -> запуск тестов -> проверки кода -> ревью изменений. В этом рабочем процессе Agent становится активным участником реализации, валидации и ревью.
  1085→
  1086→### Практика 7: Расширяйте контекст Agent через MCP
  1087→
  1088→Информация, нужная Agent, не всегда живёт внутри репозитория: таск-трекеры, CI/CD, схемы БД, API-документация. MCP позволяет Agent получать контекст напрямую из подключённых инструментов, расширяя его от «репозиторного исполнителя» до «коллаборативного узла в реальной инженерной среде».
  1089→
  1090→### Практика 8: Сохраняйте повторяющиеся рабочие процессы как Skills
  1091→
  1092→Если промпт-паттерн или поток задач используется повторно — превратите его в Skill. Это смещает использование Agent от разовых разговоров к workflow-ориентированному выполнению. По мере роста библиотеки навыков поведение Agent становится более согласованным и предсказуемым.
  1093→
  1094→### Практика 9: Автоматизируйте стабильные рабочие процессы
  1095→
  1096→Когда Skill работает надёжно — настройте автоматизацию: по расписанию или по триггеру. Например: генерация release notes при публикации, автоматическое исследование упавших CI-запусков, сканирование на баги, ежедневные отчёты.
  1097→
  1098→### Практика 10: Управляйте сессиями Agent осознанно
  1099→
  1100→Сессия — это не просто история чата, а **рабочий контекст**, накапливающий контекст, промежуточные рассуждения и результаты выполнения. Правила:
  1101→- **Отдельная сессия для каждой задачи** — не смешивайте несвязанные задачи
  1102→- **Избегайте слишком длинных сессий** — используйте `/compact` для сжатия контекста
  1103→- **Новая сессия для ответвлений** — новые направления исследования — в отдельной сессии
  1104→- **Периодически сжимайте исторический контекст** — суммаризируйте старые части разговора
  1105→

  1108→## 24. Решение частых проблем
  1109→
  1110→> **Источник:** синтез из [ZCode Docs — Feedback & Support](https://zcode.z.ai/en/newdocs/feedback) + [Z.AI Best Practices](https://docs.z.ai/devpack/resources/best-practice) + [ZCode Changelog](https://zcode.z.ai/en/changelog)
  1111→
  1112→### Agent не реагирует / зависает
  1113→
  1114→1. Проверьте подключение к модели: Settings -> Model Settings
  1115→2. Проверьте квоту: Usage Stats -> Coding Plan
  1116→3. Попробуйте перезапустить задачу: Ctrl+N -> New Task
  1117→4. Используйте `/compact` для сжатия контекста
  1118→
  1119→### Модель не отвечает / ошибки API
  1120→
  1121→1. Проверьте правильность API-ключа
  1122→2. Убедитесь, что Base URL указан корректно
  1123→3. Проверьте баланс/квоту на платформе провайдера
  1124→4. При ошибке rate limit — подождите и повторите
  1125→
  1126→### Agent теряет контекст в длинных задачах
  1127→
  1128→1. Используйте `/compact` для сжатия контекста
  1129→2. Используйте Goal Mode для автоматических итераций
  1130→3. Не смешивайте разные задачи в одной сессии
  1131→4. При необходимости начните новую задачу с кратким описанием предыдущего прогресса
  1132→
  1133→### Квота закончилась посреди задачи
  1134→
  1135→1. Проверьте текущий баланс: Usage Stats -> Coding Plan
  1136→2. Переключитесь на другую модель/провайдер
  1137→3. Подпишитесь на план или пополните баланс
  1138→4. Задача сохранится — можно продолжить после пополнения
  1139→
  1140→### Изменения не отображаются в файле
  1141→
  1142→1. Проверьте, что Agent работает с правильной директорией проекта
  1143→2. Проверьте права доступа к файлам
  1144→3. Откройте Review-панель (правая панель) для просмотра всех изменений
  1145→4. Используйте Git diff для сравнения
  1146→
  1147→### Ошибки при запуске на Windows
  1148→
  1149→1. Убедитесь, что установщик запущен с правами администратора
  1150→2. Проверьте антивирус — он может блокировать выполнение
  1151→3. Проверьте логи: `%USERPROFILE%\.zcode\logs`
  1152→4. Отправьте отчёт через встроенную форму обратной связи
