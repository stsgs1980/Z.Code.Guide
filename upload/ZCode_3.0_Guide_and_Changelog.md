## 1. Что такое ZCode 3.0

> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome)

ZCode — это **Agentic Development Environment (ADE)**, среда разработки, построенная вокруг AI-агента. Ключевая идея: вы описываете задачу на естественном языке, а Agent сам планирует, пишет код, тестирует и проверяет. В отличие от обычного автодополнения, Agent работает **долго и стабильно** — от постановки задачи до финальной проверки.

### Две ключевые силы ZCode

| Сила | Описание |
|---|---|
| **Длинные задачи (Long Horizon Tasks)** | Agent держит контекст от планирования до верификации — понимание требований, файлы, терминал, браузер, Git — всё в одной задаче |
| **Стабильность** | Саморазработанный ZCode Agent не теряет нить выполнения даже в многочасовых задачах с сотнями шагов |

### Основные возможности

- **Длинные задачи**: в одном таске — понимание требований, планирование, код, верификация, Review
- **Стабильный контекст**: файлы + терминал + браузер + режимы выполнения + Git — Agent ничего не забывает
- **Собственный Agent-флоу**: задачи, права, контекст, вызовы инструментов и Review — всё вокруг ZCode Agent
- **Мультиустройственное продолжение**: десктоп, мобильный Remote и Feishu/WeChat Bot — один и тот же таск на всех
- **Безопасность**: опасные команды, изменение файлов и высокопривилегированные действия — через подтверждение
- **Расширяемость**: Skills, Commands, Subagents, Plugins, MCP-серверы — настраивайте Agent под свою команду

## 2. Установка и первый запуск

> **Источник:** [ZCode Docs — Install](https://zcode.z.ai/en/newdocs/install)

### Скачивание

Перейдите на [zcode.z.ai](https://zcode.z.ai) и нажмите **Download**. Текущая версия: **3.0.1**.

## 3. API Key Setup — подключение моделей

> **Источник:** [ZCode Docs — Configuration (API Key Setup)](https://zcode.z.ai/en/newdocs/configuration)

ZCode поддерживает три способа подключения AI-сервисов:

| Способ | Описание |
|---|---|
| **BigModel** | Аккаунт Zhipu — для Китая. Поддержка GLM Coding Plan, ресурсные пакеты, предоплата |
| **Z.AI** | Для международных пользователей. USD-ценообразование, бесплатная дневная квота |
| **Сторонние провайдеры** | Любой сервис, совместимый с протоколами Anthropic / OpenAI |

### Рекомендуемый вариант

**Для международных пользователей:** подпишитесь на GLM Coding Plan через Z.AI (USD-ценообразование) — получите доступ к GLM-5.2 с бесплатной дневной пробной квотой.

**Для пользователей из Китая:** подпишитесь через BigModel — те же модели, но с более выгодной ценовой политикой.

### Точки входа для настройки

**Способ 1: Экран приветствия при первом запуске**

При первом открытии ZCode (если нет подключённых моделей) предложит:
- **Continue with Z.ai** — авторизация через аккаунт Z.AI
- **Continue with BigModel** — авторизация через Zhipu BigModel
- **Use API key** — ввести ключ вручную и перейти к настройкам моделей

После выбора Z.ai или BigModel откроется процесс авторизации. При успешной аутентификации аккаунт привязывается автоматически.

**Способ 2: Селектор моделей**

После входа в ZCode кликните на имя модели в поле чата → **Manage Models** внизу списка → откроется панель **Settings -> Model Settings**.

### Подключение BigModel

1. Откройте панель Model Settings
2. Выберите **BigModel** из списка провайдеров слева
3. Подключите аккаунт и включите переключатель
4. Используйте переключатель в правом верхнем углу для выбора режима: **Coding Plan** или **API Key**

**Бесплатная пробная квота:** новые пользователи получают trial-план сразу при подключении BigModel — без оплаты, с бесплатной дневной квотой для флагманских GLM-моделей. Страница провайдера показывает текущий баланс и использование в реальном времени.

**Подписка на Coding Plan внутри ZCode:** на странице BigModel доступны планы GLM Coding (Lite / Pro / Max) с ежемесячной, квартальной и годовой оплатой. Можно завершить покупку прямо в приложении.

**Подключение через API Key:**
1. Переключите режим подключения на **API Key**
2. Base URL по умолчанию: `https://open.bigmodel.cn/api/anthropic`
3. Введите API-ключ с платформы Zhipu
4. Модели по умолчанию: GLM-5.2, GLM-5-Turbo, GLM-5V-Turbo
5. Нажмите **Add Model** для добавления других моделей

### Подключение Z.AI

Z.AI — вариант для международных пользователей. Настройка аналогична BigModel:
1. Откройте панель Model Settings
2. Выберите **Z.ai** из списка провайдеров
3. Подключите аккаунт и включите переключатель
4. Переключатель Coding Plan / API Key в правом верхнем углу

Base URL для API Key: `https://api.z.ai/api/anthropic`

### Подключение сторонних провайдеров

| Провайдер | Base URL | Модели |
|---|---|---|
| **Anthropic (Claude)** | `https://api.anthropic.com` | claude-fable-5, claude-opus-4-8, claude-sonnet-4-6, claude-haiku-4-5 |
| **OpenRouter** | `https://openrouter.ai/api` | Любые модели OpenRouter |

| **MiniMax** | `https://api.minimaxi.com/anthropic` | MiniMax-M3, MiniMax-M2.5 |

Выберите канал из селектора моделей в чате и отправьте короткую тестовую инструкцию. Если модель отвечает стабильно — настройка завершена.

```
+-------------------------------------------------------------+

|          |                            |                     |
|  Файлы   |      Чат с Agent          |  Git tools          |

|          |                            |                     |
+----------+----------------------------+---------------------+

```

### Элементы интерфейса

| Элемент | Расположение | Что делает |
|---|---|---|
| **Боковая панель (левая)** | Слева | Дерево файлов + таймлайн задач, сгруппированных по дате |
| **Центральная область** | Центр | Чат с Agent + просмотр/редактирование кода |

| **Поле ввода чата** | Внизу центра | Ввод инструкций, `/` команды, `$` навыки, `@` подагенты |

## 5. Работа с ZCode Agent — базовый рабочий процесс

> **Источник:** [ZCode Docs — Welcome](https://zcode.z.ai/en/newdocs/welcome) + [Z.AI Best Practices](https://docs.z.ai/devpack/resources/best-practice)

### Простая задача

1. Откройте чат: **Cmd+N** (Mac) / **Ctrl+N** (Win) → «New Task»
2. Напишите инструкцию на естественном языке
3. Agent автоматически: исследует проект, создаст файлы, напишет код, запустит проверки
4. Следите за прогрессом в реальном времени

### Что делает Agent в процессе

| Шаг | Что происходит |
|---|---|
| **Exploring** | Agent исследует проект: ищет файлы, читает структуру |
| **Planning** | Составляет план: какие файлы создать/изменить |
| **Writing** | Пишет код, создаёт файлы |
| **Running** | Выполняет команды в терминале (npm install, npm test и т.д.) |
| **Verifying** | Проверяет результат: запускает тесты, линтер |
| **Reviewing** | Показывает финальные изменения: +N строк, -M строк |

### Как давать инструкции Agent — 4 элемента эффективного промпта

В сложном проекте эффективное описание задачи обычно включает четыре элемента:

| Элемент | Описание | Пример |
|---|---|---|
| **Goal** | Что нужно построить или изменить | «Исправь баг авторизации» |
| **Context** | Релевантные файлы, ошибки, документация | «Файл auth.ts, строка 42, ошибка E401» |
| **Constraints** | Ограничения: стандарты, архитектура, зависимости | «Используй JWT, не меняй схему БД» |
| **Done when** | Критерий завершения | «Тесты auth.test.ts проходят» |

**Хорошо:** «Исправь баг авторизации в auth.ts (строка 42, ошибка E401). Используй JWT, не меняй схему БД. Готово, когда auth.test.ts проходит.»

**Плохо:** «Почини авторизацию»

## 6. Режимы выполнения (Execution Modes)

> **Источник:** [ZCode Docs — Goal Mode](https://zcode.z.ai/en/newdocs/goal) (раздел «Combine with execution modes»)

ZCode Agent поддерживает несколько режимов выполнения, которые определяют, сколько действий требуют подтверждения:

| Режим | Описание | Когда использовать |
|---|---|---|
| **Full Access / Auto Edit** | Agent выполняет действия без постоянных подтверждений | Для длинных задач, Goal Mode — минимум прерываний |
| **По умолчанию** | Опасные действия требуют подтверждения | Для повседневной разработки |
| **Strict / Manual** | Каждое действие требует подтверждения | Для критических изменений |

**Как переключить:** нажмите **Shift+Tab** (когда фокус в поле ввода чата) для циклического переключения режимов.

**Совет:** Для длинных goal-driven задач комбинируйте Goal Mode с Full Access — это минимизирует прерывания и позволяет итерациям идти непрерывно.

## 7. Goal Mode — режим целей для сложных задач

> **Источник:** [ZCode Docs — Goal Mode](https://zcode.z.ai/en/newdocs/goal)

### Когда использовать

- Задача легко описывается одним предложением, но требует много итераций
- Примеры: «Отрефактори весь модуль, чтобы тесты проходили», «Исправь все TypeScript-ошибки», «Получи Lighthouse-оценку выше 90»

### Как работает

1. Вы ставите цель через `/goal`
2. Agent работает итеративно — в конце каждой итерации **автоматически проверяет** цель
3. Если цель не достигнута — начинается следующая итерация
4. Задача завершается только когда цель **верифицирована как выполненная**
5. Вам не нужно повторно писать «продолжай» — Agent продолжает сам

### Команды Goal Mode

| Команда | Описание |
|---|---|
| `/goal <objective>` | Установить цель сессии |
| `/goal replace <objective>` | Заменить текущую цель |
| `/goal pause` | Поставить цель на паузу |
| `/goal resume` | Возобновить цель |
| `/goal clear` | Удалить цель |

### Совет по формулировке цели

Делайте цель **конкретной и проверяемой**:  
«Исправь все TypeScript-ошибки компиляции и добейся, чтобы `pnpm test` проходил» — лучше, чем «исправь ошибки».

### Что происходит после установки цели

1. **Карточка цели** появляется в панели сводки (правый верхний угол) — статус (active/paused/complete), затраченное время, токены, количество итераций
2. **Автоматическая верификация** после каждой итерации
3. **Можно вмешаться в любой момент**: заменить цель, поставить на паузу, очистить

## 8. Command — встроенные и пользовательские команды

> **Источник:** [ZCode Docs — Command](https://zcode.z.ai/en/newdocs/commands)

### Встроенные команды

| Команда | Назначение |
|---|---|
| `/goal` | Показать, установить, заменить, приостановить, возобновить или очистить цель текущей сессии |
| `/compact` | Сжать контекст текущего разговора с сохранением ключевой информации — полезно для продолжения длинных бесед |

### Как использовать

Введите `/` в поле ввода — откроется панель команд, организованная по группам **Commands** и **Skills**. Продолжайте печатать для фильтрации.

### Создание пользовательской команды

1. Откройте **Settings -> Commands**
2. Нажмите **Create new command**
3. Заполните поля:

| Поле | Описание |
|---|---|
| **Scope** | User (доступно во всех workspace) или Workspace (только текущий проект) |
| **Name** | Имя команды, вызывается как `/command-name` |
| **Description** | Краткое описание, отображается в пикере команд |
| **Argument hint** | Подсказка параметра, например `<file-path>` |
| **Prompt** | Содержимое промпта, отправляемое Agent при запуске команды |

Команды хранятся как `.md`-файлы в `~/.zcode/commands/` (на уровне пользователя) или в директории проекта (на уровне workspace).

### Импорт команд из внешних Agent

Если у вас есть команды в Claude Code или другом Agent — не нужно создавать их заново:
1. Откройте **Commands** в настройках ZCode
2. Нажмите **Import commands from external Agent** в правом верхнем углу
3. Выберите нужные команды и подтвердите

### Когда использовать Command vs Skill

- **Command** — для простого сохранённого промпта
- **Skill** — когда нужен полный рабочий метод с шаблонами, чеклистами, примерами

## 9. Skill — переиспользуемые рабочие инструкции

> **Источник:** [ZCode Docs — Skill](https://zcode.z.ai/en/newdocs/skill)

### Что это

Skill — это переиспользуемая рабочая инструкция, определяемая файлом `SKILL.md`. Описывает, когда навык используется, как Agent должен работать и какой результат ожидается.

### Управление навыками

Откройте **Settings -> Skills** — каждая строка показывает имя навыка, источник, описание и переключатель включения.

- Поиск навыков по имени
- Включение/выключение переключателем
- **New Skill** в правом верхнем углу — Agent поможет создать навык прямо в чате

### Создание навыка

Навык — это директория с файлом `SKILL.md` внутри:

```
~/.zcode/skills/<skill-name>/SKILL.md
```

Минимальный `SKILL.md`:

```markdown
---
name: code-review-checklist
description: Review code changes with a focused checklist for correctness, regressions, tests, and maintainability.
---

# Code Review Checklist

Use this skill when reviewing a pull request, merge request, or local diff.

Focus on correctness, regressions, missing tests, risky API changes, and maintainability.
```

После создания: **Settings -> Skills -> Refresh** — навык появится в списке.

### Импорт навыков из внешних Agent

Поддерживается импорт из Claude Code, Codex CLI, OpenClaw, Augment, Windsurf:

1. **Settings -> Skills** -> нажмите иконку **Import** в правом верхнем углу
2. ZCode просканирует директории внешних Agent и покажет доступные навыки
3. Выберите навыки и режим импорта:
   - **Symlink** — связь с внешней директорией (изменения синхронизируются, но зависит от пути)
   - **Copy** — независимая копия (без синхронизации с источником)
4. Выберите цель импорта: **Global** (на уровне пользователя) или **Project** (текущий workspace)

### Использование навыка в чате

Введите `$` в поле ввода и выберите навык. Навык появится как тег, после которого можно продолжить запрос:

```
$code-review-checklist review my current changes
$release-notes write release notes for this change set
```

### Что стоит сделать навыком

- Задача повторяется: code review, API debugging, release notes, test reports
- Команда ожидает единообразный формат вывода
- Рабочий процесс требует фоновых знаний, чеклистов, шаблонов или примеров
- Возможность будет переиспользована в разных проектах

## 10. Subagents — подагенты для делегирования задач

> **Источник:** [ZCode Docs — Subagents](https://zcode.z.ai/en/newdocs/subagents)

### Что это

Subagents — специализированные роли, подготовленные для Agent. Вы можете превратить повторяющиеся задачи (code review, отладка тестов, release notes, проверка UI) в подагенты, чтобы активный Agent мог делегировать им целенаправленную работу.

### Использование в чате

Введите `@` в поле ввода и выберите роль из группы **Agents**:

```
@zcode-reviewer проверь текущие изменения на риск регрессии
@zcode-test-helper найди, почему этот тест падает
```

### Настройка подагентов

Подагенты определяются как Markdown-файлы:

- **На уровне пользователя** (доступны во всех workspace): `~/.zcode/cli/agents/`
- **На уровне workspace** (только текущий проект): `<workspace>/.zcode/cli/agents/`

Каждый подагент — `.md`-файл с опциональным YAML frontmatter + системный промпт:

```markdown
---
name: zcode-reviewer
description: Check changes for regression risk before committing
color: "#3b82f6"
model: glm-5.2
tools: Read, Grep, Bash
---

You are a code-review subagent focused on regression risk, edge cases, and test coverage…
```

**Поля frontmatter:**

| Поле | Описание |
|---|---|
| `name` | 3-50 символов, буквы, цифры и дефисы |
| `description` | Когда использовать — управляет автоматическим делегированием |
| `color` (опционально) | Акцентный цвет в UI, например `#3b82f6` |
| `model` (опционально) | Конкретная модель; пусто = текущая модель сессии |
| `tools` (опционально) | Ограничение доступных инструментов |

### Подагенты из плагинов

Подагенты также могут предоставляться плагинами. После включения плагина роли появляются в списке автоматически (с пометкой plugin source).

### Рекомендации по ролям

Практичная настройка обычно начинается с 3-5 ролей:
- Code review
- Test debugging
- Documentation cleanup
- UI checking
- Release notes

Каждая роль должна быть узкой с чётким триггером.

## 11. Plugin — расширение возможностей

> **Источник:** [ZCode Docs — Plugin](https://zcode.z.ai/en/newdocs/plugin)

### Что содержит плагин

Один плагин может объединять несколько компонентов:

| Компонент | Описание |
|---|---|
| **Skill** | Файлы навыков, обучающие Agent определённым способам работы |
| **Command** | Быстрые команды, вызываемые через `/` |
| **Agent** | Подагенты, зарегистрированные вместе с плагином |
| **MCP servers** | Внешние инструментальные серверы, показанные в группе Plugin MCP |
| **Hook** | Автоматизационные хуки, срабатывающие на определённых событиях |
| **LSP** | Языковые серверы для автодополнения, диагностики и т.д. |

При включении плагина все его компоненты регистрируются в текущем workspace; при выключении — отключаются вместе.

### Встроенные плагины

ZCode поставляется с набором официальных плагинов:

| Плагин | Возможности | Компоненты |
|---|---|---|
| **android-emulator** | Android-разработка и автоматизация эмулятора | 1 skill, 1 command, 1 MCP |
| **ios-simulator** | iOS-разработка и автоматизация симулятора | 1 skill, 1 command, 1 MCP |

После включения Agent может управлять Android-эмулятором или iOS-симулятором напрямую: сборка, запуск, установка, верификация UI — всё в одном разговоре.

### Управление плагинами

**Settings -> Plugins:**
- Фильтрация по имени/описанию
- Проверка источника (Official и т.д.)
- Включение/выключение переключателем
- Клик по плагину для просмотра его компонентов
- Перед выключением ZCode покажет, какие навыки, команды или MCP-серверы будут затронуты

**Важно:** изменения плагинов требуют перезагрузки Agent runtime. Текущая сессия перезагрузится автоматически после включения/выключения плагина.

## 12. MCP-серверы — подключение внешних инструментов

> **Источник:** [ZCode Docs — Plugin](https://zcode.z.ai/en/newdocs/plugin) (раздел MCP servers) + [Z.AI Best Practices — Extend Agent Context with MCP](https://docs.z.ai/devpack/resources/best-practice)

### Что это

MCP (Model Context Protocol) — стандартный способ подключения внешних инструментов и систем, чтобы Agent мог получать информацию из-за пределов репозитория:

- Платформы хостинга кода и коллаборации
- Базы данных и интерфейсы запросов
- API-сервисы и техническая документация
- Внутренние инструменты и системы автоматизации

### Как подключить

1. Откройте **Settings -> MCP Servers**
2. Добавьте конфигурацию MCP-сервера
3. Agent получит доступ к новым инструментам

MCP-серверы также могут предоставляться через плагины (см. раздел Plugin).

## 13. Edit History — редактирование отправленных сообщений

> **Источник:** [ZCode Docs — Edit History](https://zcode.z.ai/en/newdocs/edit-history)

### Что это

Edit History позволяет исправлять сообщения, уже отправленные Agent. Если инструкция неясна, отсутствует путь к файлу, не хватает ограничения или нужно изменить направление — можно отредактировать исходное сообщение, и Agent продолжит с обновлённым контекстом вместо перезапуска.

**Особенно полезно для длинных задач:** сохраняется та же модель, workspace, ветка и контекст задачи — корректируется только ключевая инструкция.

### Как использовать

1. В истории разговора наведите курсор на своё сообщение
2. Справа от сообщения появится область быстрых действий
3. Нажмите **иконку карандаша** (Edit)
4. Исходное сообщение станет редактируемым
5. Перепишите текст, используйте `@` для ссылок на файлы, `/` для команд
6. Нажмите **Send** — Agent продолжит с обновлённой инструкцией
7. Или **Cancel** — исходное сообщение останется без изменений

### Правила

- Редактировать можно только **пользовательские сообщения**, не ответы Agent
- Доступно только для **последнего хода** разговора
- Недоступно, пока задача выполняется или есть сообщения в очереди

### Типичные сценарии

| Сценарий | Пример |
|---|---|
| Исправить требование | Исправить ранее отправленную инструкцию, которая была неверной или неполной |
| Добавить контекст | Добавить путь к файлу, лог ошибки, скриншот, параметр API, ограничение |
| Изменить направление | Переключиться с «проанализируй» на «исправь», или с «реализуй» на «сначала спланируй» |
| Избежать повторной настройки | Сохранить существующий контекст задачи вместо объяснения фона заново |

## 14. Remote Control — управление с телефона

> **Источник:** [ZCode Docs — Remote Control](https://zcode.z.ai/en/newdocs/remote-control)

### Когда использовать

- Десктопная задача уже выполняется, а вам нужно отойти
- Получили быстрое обновление и хотите добавить инструкцию с телефона
- Длинная задача работает, и вы хотите проверить статус без возвращения к компьютеру

### Как подключиться

1. Кликните **иконку телефона** в левом нижнем углу ZCode
2. Появится диалог с **QR-кодом** и ссылкой для текущего workspace
3. Отсканируйте QR-код телефоном или откройте ссылку в мобильном браузере
4. Телефон подключается к текущему десктопному workspace

**Важно:** десктоп остаётся средой выполнения; телефон используется для чтения сессии, отправки сообщений и запуска действий.

### Что можно делать

- Читать последний ответ Agent и прогресс задачи
- Отправлять новую инструкцию или дополнительный контекст
- Подтверждать, продолжать или останавливать длинную задачу
- Вернуться в текущий workspace из любого места

**Ограничение:** только один телефон может быть подключён одновременно, и он имеет доступ только к workspace, уже открытым на десктопе.

## 15. Bot Channel — Feishu / WeChat / Telegram

> **Источник:** [ZCode Docs — Bot Channel](https://zcode.z.ai/en/newdocs/bot-channel)

### Remote Control vs Bot Channel

| Remote Control | Bot Channel |
|---|---|
| Быстрый доступ через QR-код | Точка входа живёт внутри чат-инструмента |
| Для временного подключения | Для длительного доступа из мессенджера |
| Один телефон одновременно | Можно пересматривать переписку с ботом |

### Создание Bot Channel

1. Откройте **Bots** в левой боковой панели
2. Нажмите **Create Bot**
3. Выберите канал для подключения

**Доступные каналы:**
- **WeChat** — сканируйте для входа и автоматической привязки
- **Feishu** — сканируйте для создания приложения, затем привяжите через сообщения
- **Telegram** — создайте бота, затем привяжите через сообщения

DingTalk, Discord и WeCom будут добавлены в будущих версиях.

### Привязка Feishu

1. Выберите Feishu в ZCode
2. Отсканируйте QR-код — ZCode автоматически создаст приложение Feishu
3. ZCode сгенерирует код привязки (pairing code)
4. В разговоре Feishu отправьте `/bind pairing-code`
5. После подтверждения бот готов к использованию

После привязки Feishu-бот вернёт список доступных команд: проверка статуса, создание задач, переключение проектов, переключение моделей, изменение режима выполнения, настройка детальности ответов.

### Управление ботами

После создания боты появляются в списке слева. Доступные настройки:
- **Bind Bot** — привязка учётных данных
- **Reply granularity** — контроль детальности ответов бота
- **Workspace access scope** — ограничение доступных workspace
- **Delete Bot** — удаление канала

### Быстрый старт

**Шаг 2 — Установка и запуск**

Требование: Node.js 18+ или новее. Два способа установки:

**Метод 1 (рекомендуемый — npx без глобальной установки):**

```bash
## Глобальная установка

## Затем запуск
chelper
```

**Шаг 3 — Пройдите мастер настройки**

В мастере используйте стрелки для выбора и Enter для подтверждения:

1. Выберите язык интерфейса

### Список команд

Помимо интерактивного мастера, Coding Tool Helper поддерживает запуск конкретных команд через `coding-helper` или `chelper` с аргументами:

```bash
# Запуск мастера инициализации
coding-helper init

# Управление языком

coding-helper auth --help            # Справка по командам авторизации

# Общие

coding-helper --version              # Показать версию
```

### Решение проблем

При возникновении неполадок сначала запустите `coding-helper doctor` для диагностики.

**1. Сетевая ошибка (Network Error)**

- **Проблема:** При сохранении или валидации API KEY появляются ошибки сети.
- **Решение:** Проверьте подключение к сети или настройте прокси.
- **Примечание:** Node.js не использует системный прокси автоматически. Установите переменные окружения `HTTP_PROXY` и `HTTPS_PROXY`:

```bash
export HTTP_PROXY=http://your.proxy.server:port
export HTTPS_PROXY=http://your.proxy.server:port
```

**2. Таймаут сети**

- **Проблема:** При установке или запуске инструментов появляются ошибки таймаута.
- **Решение:** Проверьте сетевое подключение или настройте прокси.

**3. Недостаточно прав (EACCES: permission denied)**

- **Проблема:** `npm install -g` выдаёт ошибку EACCES.
- **Решение:**
  - Используйте `sudo` (macOS/Linux)
  - Запустите терминал от имени администратора (Windows)
  - Используйте `npx @z_ai/coding-helper` вместо глобальной установки
  - Используйте nvm для управления версиями Node.js и избегания проблем с правами

**4. Некорректный статус плагина в Claude Code Marketplace**

- **Проблема:** Статус плагина отображается некорректно (например, «не установлен», хотя уже установлен).
- **Решение:** Запустите `claude update` для обновления Claude Code до версии 2.0.70 или новее.

**5. Недействительный API Key**

- **Проблема:** API Key помечен как недействительный.
- **Решение:**
  - Проверьте корректность скопированного ключа
  - Убедитесь, что на связанном аккаунте достаточный баланс

**6. Таймаут подключения**

- **Проблема:** Время подключения к сервису истекло.
- **Решение:**
  - Проверьте сетевое подключение
  - Проверьте настройки брандмауэра
  - Убедитесь, что Node.js и сетевое окружение готовы

## 23. Лучшие практики работы с Coding Agent

> **Источник:** [Z.AI Developer Docs — Best Practices for Coding Agents](https://docs.z.ai/devpack/resources/best-practice)

Основано на официальных рекомендациях Z.AI.

### Практика 1: Относитесь к Coding Agent как к коллаборатору, а не к одноразовому помощнику

Распространённая ошибка — использовать Agent как инструмент «вопрос-ответ»: задал вопрос, получил код, закончил. На практике ценность Coding Agent складывается не только из возможностей модели, но и из **рабочего процесса вокруг неё**. Через файлы конфигурации проекта, интеграции инструментов и переиспользуемые навыки вы постоянно формируете поведение Agent, чтобы оно соответствовало рабочему процессу вашей команды.

### Практика 2: Контекст важнее трюков с промптами

В сложном проекте эффективное описание задачи включает четыре элемента: Goal, Context, Constraints, Done when. Структурированный ввод задачи снижает ненужные догадки и делает изменения Agent более согласованными и удобными для проверки.

### Практика 3: Планируйте перед выполнением сложных задач

Для сложных запросов Agent наиболее эффективен, когда сначала планирует, а потом действует. Используйте Goal Mode или явно просите Agent: «Сначала составь план, затем реализуй». Это снижает логические ошибки, ненужные переделки и повторные ревизии.

### Практика 4: Сохраняйте повторяющиеся правила в файлах конфигурации проекта

Многие промпты повторяют одни и те же правила: структура директорий, команды сборки, workflow тестирования, стандарты кода, процесс подачи PR. Если эти правила повторять в каждом промпте — это неэффективно и ведёт к дрифту инструкций. Перенесите их в файлы конфигурации проекта (Skills, Commands).

**Простое правило:** временные инструкции — в промпте, долговременные правила — в файлах конфигурации проекта.

### Практика 5: Среда выполнения определяет, что может Agent

Многие проблемы, которые разработчики относят к возможностям модели, на самом деле вызваны неполной или плохо настроенной средой выполнения. Убедитесь, что:
- Рабочая директория проекта доступна
- Права на чтение/запись файлов настроены
- Команды сборки и тестирования работают
- Внешние инструменты и сервисы доступны

### Практика 6: Вовлекайте Agent в полный цикл разработки

Agent должен не только генерировать код, но и участвовать в полном цикле: реализация -> написание тестов -> запуск тестов -> проверки кода -> ревью изменений. В этом рабочем процессе Agent становится активным участником реализации, валидации и ревью.

### Практика 7: Расширяйте контекст Agent через MCP

Информация, нужная Agent, не всегда живёт внутри репозитория: таск-трекеры, CI/CD, схемы БД, API-документация. MCP позволяет Agent получать контекст напрямую из подключённых инструментов, расширяя его от «репозиторного исполнителя» до «коллаборативного узла в реальной инженерной среде».

### Практика 8: Сохраняйте повторяющиеся рабочие процессы как Skills

Если промпт-паттерн или поток задач используется повторно — превратите его в Skill. Это смещает использование Agent от разовых разговоров к workflow-ориентированному выполнению. По мере роста библиотеки навыков поведение Agent становится более согласованным и предсказуемым.

### Практика 9: Автоматизируйте стабильные рабочие процессы

Когда Skill работает надёжно — настройте автоматизацию: по расписанию или по триггеру. Например: генерация release notes при публикации, автоматическое исследование упавших CI-запусков, сканирование на баги, ежедневные отчёты.

### Практика 10: Управляйте сессиями Agent осознанно

Сессия — это не просто история чата, а **рабочий контекст**, накапливающий контекст, промежуточные рассуждения и результаты выполнения. Правила:
- **Отдельная сессия для каждой задачи** — не смешивайте несвязанные задачи
- **Избегайте слишком длинных сессий** — используйте `/compact` для сжатия контекста
- **Новая сессия для ответвлений** — новые направления исследования — в отдельной сессии
- **Периодически сжимайте исторический контекст** — суммаризируйте старые части разговора

## 24. Решение частых проблем

> **Источник:** синтез из [ZCode Docs — Feedback & Support](https://zcode.z.ai/en/newdocs/feedback) + [Z.AI Best Practices](https://docs.z.ai/devpack/resources/best-practice) + [ZCode Changelog](https://zcode.z.ai/en/changelog)

### Agent не реагирует / зависает

1. Проверьте подключение к модели: Settings -> Model Settings
2. Проверьте квоту: Usage Stats -> Coding Plan
3. Попробуйте перезапустить задачу: Ctrl+N -> New Task
4. Используйте `/compact` для сжатия контекста

### Модель не отвечает / ошибки API

1. Проверьте правильность API-ключа
2. Убедитесь, что Base URL указан корректно
3. Проверьте баланс/квоту на платформе провайдера
4. При ошибке rate limit — подождите и повторите

### Agent теряет контекст в длинных задачах

1. Используйте `/compact` для сжатия контекста
2. Используйте Goal Mode для автоматических итераций
3. Не смешивайте разные задачи в одной сессии
4. При необходимости начните новую задачу с кратким описанием предыдущего прогресса

### Квота закончилась посреди задачи

1. Проверьте текущий баланс: Usage Stats -> Coding Plan
2. Переключитесь на другую модель/провайдер
3. Подпишитесь на план или пополните баланс
4. Задача сохранится — можно продолжить после пополнения

### Изменения не отображаются в файле

1. Проверьте, что Agent работает с правильной директорией проекта
2. Проверьте права доступа к файлам
3. Откройте Review-панель (правая панель) для просмотра всех изменений
4. Используйте Git diff для сравнения

### Ошибки при запуске на Windows

1. Убедитесь, что установщик запущен с правами администратора
2. Проверьте антивирус — он может блокировать выполнение
3. Проверьте логи: `%USERPROFILE%\.zcode\logs`
4. Отправьте отчёт через встроенную форму обратной связи

## Общая картина эволюции ZCode

| Период | Фокус |
|---|---|
| **2.7 - 2.9** | Оплата, подписки, терминал, обратная связь |
| **2.10 - 2.11** | UX-полировка: поиск чатов, шаблоны отзывов |
| **2.12 - 2.13** | Удаление задач, общие навыки, Markdown-изображения |
| **3.0.0 - 3.0.1** | **Собственный Agent, GLM-оптимизация, Zread, Git-граф, новая визуальная система, восстановление сессий V2** |

**Главный тренд:** ZCode переходит от интеграции с третьими Agent'ами к **собственной экосистеме** с GLM-ядром, что даёт значимый прирост в качестве выполнения задач.
